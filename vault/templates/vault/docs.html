Credential Vault

Encrypted storage for passwords, SSH keys, and certificates — personal or shared with a team via containers.

Credential Types
  • Password — URL, username, and encrypted password.
  • SSH Key — Encrypted private key, optional passphrase, and plaintext public key.
  • Certificate — Encrypted private key and plaintext certificate PEM.
Containers & Sharing

Credentials can live in a Container (a folder, optionally nested inside another) instead of staying personal. A container is shared with one or more Teams, each with Read or Read/Write access. Everyone in any team with access to a container can see and copy its credentials; only Read/Write members can edit or delete them.

  • Personal — No container, no team; only you can see it.
  • Team (legacy) — Shared directly with a team, no container. Still supported, but new sharing should use containers instead.
  • Container — Shared with whichever teams have access to that container. Moving a credential between containers, or between Personal and a container, automatically re-encrypts its secret (and shared notes) for the new audience — no need to retype anything.
Sidebar Navigation

The sidebar on /vault/ splits your containers into two groups:

  • Personal — containers you created that aren't shared with any team.
  • Shared — containers shared with at least one of your teams, grouped by team. A container shared with more than one team appears once under each.

Click any container to filter the list; click "All" to see everything, or "Personal (uncategorized)" for credentials with no container at all. Use the search box to filter by name, username, or URL, and the tag dropdown to filter by tag — all three filters combine. Each section (and each container with sub-containers) has a −/+ button to collapse it.

Staff users see a shortcut next to shared containers that jumps straight to that container's access-grant settings.

Creating Containers

Use the + New button above the sidebar to create a container (name and optional parent) directly from the vault — you'll have access to it immediately as its creator. Sharing it with a team is a separate step, done by staff at Settings → App → Vault.

Notes

Each credential can have a private note. Owners can optionally toggle Share notes with team to make the note visible (and editable by Read/Write members) to the same audience as the credential's container — independent of whether the secret itself is shared.

Deleting Credentials

Deleting a credential is a soft delete — it's hidden from the list but not destroyed, so it can be recovered if needed.

Copying Secrets

Secrets are never shown in plaintext. Use the button to copy the decrypted secret directly to your clipboard via a secure AJAX request.

Expiry Warnings

Credentials with an expiry date within 30 days show a warning badge in the list.

Importing

Import credentials from a KeePass .kdbx file or a KeePassX .xml export via the Import button. Entries that would duplicate an existing credential name are skipped.

SECRET_KEY Rotation Warning

Each user's vault key is encrypted with a key derived from SECRET_KEY. Rotating SECRET_KEY will make all vault credentials unreadable. Export or re-enter credentials before rotating.
