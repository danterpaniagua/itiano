Contacts

Contacts enrich user identities with real names and communication channels. A Contact can exist without a linked user account.

Ticket Display

When a ticket's requester has a linked Contact, the ticket list and detail show the contact's full name instead of the username.

Channel Types
TypeDescription
EmailStores an email address (display only in this version).
PhoneStores a phone number (display only in this version).
POSTHTTP POST endpoint with URL, custom headers, and a body template.
HangoutsStores a Google Hangouts identifier (display only).
JiraStores a Jira username (display only).
TelegramStores a Telegram username (display only).
POST Channel Body Variables

Use Django template syntax in the body field. All variables below are available when composing the body of a POST channel.

Variable Source Type Example
{% verbatim %}{{ contact.first_name }}{% endverbatim %} Contact string Juan
{% verbatim %}{{ contact.last_name }}{% endverbatim %} Contact string Pérez
{% verbatim %}{{ ticket.id }}{% endverbatim %} Ticket integer 42
{% verbatim %}{{ ticket.title }}{% endverbatim %} Ticket string VPN no conecta desde oficina
{% verbatim %}{{ ticket.state }}{% endverbatim %} Ticket string open, in_progress, closed

Variable substitution is applied at send time. The test button sends the literal body without substitution.

Test Button

POST channels have a test button on the contact detail page. The test fires a real HTTP POST with the saved URL, headers, and body. The body and headers are editable before sending. The response status code and body are shown inline.

Delivery

Automatic notification delivery (triggering POST channels when a ticket state changes) is planned for a future version.
