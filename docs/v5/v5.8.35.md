# v5.8.35 — Settings: Closed Status Flag for Ticket Statuses

## Goal

Add an explicit, staff-configurable **Closed Status** flag to `JiraStatusConfig` (`/settings/jira/`), decoupled from the existing `category` field. This is groundwork for a future Time by Status revamp (deferred — see `.claude/deferred_time_by_status_revamp.md`) — no report/calculation logic changes in this scope.

## Current State (before this scope)

`timetracking/views.py` derived "terminal" statuses implicitly from `category == 'done'` (`_terminal_statuses`), with a hardcoded fallback of `{'done', 'descartado'}` when no `JiraStatusConfig` rows exist. `category` is also used for column ordering and status colors, so it was overloaded — a status could reasonably be categorized `done` for display purposes without necessarily meaning "stop counting time here," or vice versa.

## Decisions

| Question | Decision |
|---|---|
| Setting scope | **Global** (`JiraStatusConfig` is system-wide, no per-user variant exists today) |
| Field name / label | `is_terminal` model field, labeled **"Closed Status"** in the UI |
| Default | Checked (`True`) for any status named "Done" or "Descartado" (case-insensitive); unchecked otherwise |
| Relationship to `category` | Independent field — `category` keeps driving column order/colors; `is_terminal` is the new, separate signal |

## Approved Mockup

- `docs/mockup/mockup_jira_settings_closed_status.html` — desktop table + mobile card layout with the Closed Status checkbox column

## Implemented

### Model (`settings_hub/models.py`)
- Added `is_terminal = models.BooleanField(default=False, verbose_name='Closed Status')` to `JiraStatusConfig`.
- Migration `0003_jirastatusconfig_is_terminal`: adds the field, then a `RunPython` data migration backfilling `is_terminal=True` for existing rows named "Done" or "Descartado" (case-insensitive).

### Settings UI (`settings_hub/templates/settings_hub/jira_settings.html`)
- "Closed Status" checkbox column added to the Ticket Statuses table (desktop table + `d-md-none` mobile card layout).
- Checkbox auto-submits a toggle form on change (`onchange="this.form.submit()"`) — no separate save button.
- Add-status form: "Closed Status" checkbox alongside status name / category fields.

### View (`settings_hub/views.py`)
- `JiraStatusAddView`: accepts and persists `is_terminal` from the add form.
- New `JiraStatusToggleTerminalView` (`settings-jira-status-toggle-terminal` URL) flips the flag on an existing row.

### Admin (`settings_hub/admin.py`)
- `is_terminal` added to `list_display` and `list_filter`.

## Out of Scope (deferred to the Time by Status revamp)

- Any change to how `timetracking/views.py` computes `_TERMINAL_STATUSES` or `status_totals` — the report still uses `category == 'done'`; wiring `is_terminal` into the report calculation happens in the revamp.
- The Time by Status miscalculation bug itself (inflated hours for Done/Descartado) — resolved as part of the revamp, using this new setting.
- Any redesign of the Time by Status card UI.
