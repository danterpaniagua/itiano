# v5.8.1 — In Progress Panel: Total and Today Columns

## Status

**Delivered.**

## Goal

Add a second time column to the "In Progress / Now" panel so each ticket shows both its total time in In Progress and the time accumulated today. Also fixes inflated Time by Tag totals for weekly and monthly ranges.

## In Scope

- Compute `jira_today` per ticket: time in the current In Progress segment since midnight today
- Pass both `jira_ongoing` (total) and `jira_today` (today only) in each `today_rows` entry
- Desktop table: two columns — "Total" and "Today"
- Mobile card: both values shown inline
- Fix Time by Tag: use In Progress time only for segments that started within the selected range (no ongoing-from-before exception), preventing impossible multi-day totals for weekly/monthly views

## Out of Scope

- Working-hours-based calculation (deferred to v5.9.0)
- Today column in the pivot or Time by Status panels
- Tickets not currently In Progress

## Technical Changes

- `timetracking/views.py` — `DailyReportView`:
  - `today_start` + per-ticket `today_secs` computation
  - `ticket_ip_range_secs`: IP-only, within-range-only seconds for tag attribution
  - `tag_seconds` now uses `ticket_ip_range_secs` instead of `ticket_range_secs`
- `timetracking/templates/timetracking/report.html`:
  - Desktop: "Total" and "Today" columns in In Progress table
  - Mobile: both values inline

## Acceptance Criteria

- In Progress panel shows Total and Today columns ✅
- Today ≤ Total for tickets in progress since before today ✅
- Week/Month range selection does not affect In Progress columns ✅
- Time by Tag shows In Progress-only time for the selected range (no 49d-type inflation) ✅
