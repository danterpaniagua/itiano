# v5.8.34 — Time Report: Tag Hierarchy Settings

## Goal

System-wide configuration for the tag hierarchy used by the Time Report cards.
Staff configures Projects → Services → Environments (per service) via a new card in `/settings/app/`.
The Time by Project card on the report uses this hierarchy to show project totals with service breakdowns.

## Approved Mockups

- `docs/mockup/mockup_app_settings_hub.html` — hub card placement
- `docs/mockup/mockup_time_report_settings.html` — settings page UI

## In Scope

### Models (`timetracking` app)

Three normalized models, cascade-deleting downward:

**`ReportProject`**
- `tag_name` CharField(100) — matches existing Tag names

**`ReportService`**
- `tag_name` CharField(100)
- `project` FK → ReportProject (CASCADE)

**`ReportEnvironment`**
- `tag_name` CharField(100)
- `service` FK → ReportService (CASCADE)

Migration for all three models.
Django admin registration for all three.

### Settings page `/settings/time-report/`

New view `TimeReportSettingsView` in `settings_hub/views.py`.
New URL `path('time-report/', ..., name='settings-time-report')` in `settings_hub/urls.py`.
New template `settings_hub/templates/settings_hub/time_report_settings.html`.

Page sections:
- **Projects & Services**: list of `ReportProject` entries, each showing its `ReportService` children indented; inline add-service form per project; env pills per service (inline add via dropdown, remove via ×); remove project cascades children
- Add-project row: dropdown of all existing `Tag` objects + "New tag?" link to `/settings/tags/`
- Add-service row (per project): same dropdown
- Add-environment inline (per service): dropdown of all `Tag` objects

POST actions (all redirect back to the same page):
- `action=add_project` + `tag_name`
- `action=remove_project` + `project_id`
- `action=add_service` + `project_id` + `tag_name`
- `action=remove_service` + `service_id`
- `action=add_env` + `service_id` + `tag_name`
- `action=remove_env` + `env_id`

### Hub card (`settings_hub/templates/settings_hub/app_hub.html`)

Add "Time Report" card (amber `text-warning`, `bi-clock-history` icon) with badges: Projects · Services · Environments. Links to `settings-time-report`.

### Time by Project card (updated, `timetracking/templates/timetracking/report.html`)

When `ReportProject` table is non-empty:
- Replace pill-selection UI with hierarchy view
- Project row: project `tag_name` + total IP seconds (sum of all its services' tag seconds)
- Service rows (indented): service `tag_name` + individual IP seconds
- Both use relative bar widths (max = largest project total)
- JS reads a `report_hierarchy_json` context variable (see view change)

When `ReportProject` is empty: existing pill-selection UI unchanged (fallback).

### View change (`timetracking/views.py`)

In `DailyReportView`, after computing `tag_seconds`:
- Query `ReportProject.objects.prefetch_related('services')` 
- Build `report_hierarchy`: list of `{project, total_secs, display, services: [{name, secs, display}]}`
- Serialize as HTML-safe JSON → `report_hierarchy_json` in context

## Out of Scope

- Time by Environment card changes (environments stored but not yet used in display — deferred)
- Per-environment breakdown within the Time by Project card (deferred)
- Per-user configuration (system-wide only)
- Tag rename cascades (user responsibility; no FK to Tag model)
