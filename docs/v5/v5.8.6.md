# v5.8.6 — Fix Back Navigation from Jira Ticket to Time Report

## Goal

When a user clicks a ticket link in `/time/report/` and then presses the browser Back button, they should return to the report — not land on `/jira/`.

## Current State

Links in the time report (In Progress panel and Status History pivot) point to `{% url 'jira-ticket-detail' issue_key %}`. Pressing Back from that page navigates to `/jira/` instead of `/time/report/`. This is caused by a redirect in `jira-ticket-detail` that pushes an extra entry onto the browser history stack.

## Investigation Required

Before implementing, verify what redirect is occurring:

- Check `jira_integration/views.py` — `ticket_detail` — for any `HttpResponseRedirect` or `redirect()` call that may fire conditionally (e.g., ticket not found, missing field, auth redirect).
- If a redirect exists and is avoidable: remove or fix it.
- If no redirect exists but the issue persists: add a `?back=` query param to report ticket links and render a "Back to Report" button in the jira detail template.

## In Scope

- Identify and fix the redirect causing incorrect Back navigation
- If redirect fix is insufficient: add `?back=<url>` to all ticket links in `report.html` and `entry_list.html`, and render a "← Back" link in `jira_integration/templates/jira_integration/ticket_detail.html` when the param is present

## Out of Scope

- Changing back-navigation behavior for any page other than the time report
- Breadcrumb or global navigation changes

## Technical Changes (conditional on investigation)

**Option A — fix redirect:**
- `jira_integration/views.py`: remove or guard the problematic redirect

**Option B — back param:**
- `timetracking/templates/timetracking/report.html`: append `?back=/time/report/?range={{ range_param }}` to all `<a href="{% url 'jira-ticket-detail' ... %}">` links
- `timetracking/templates/timetracking/entry_list.html`: append `?back=/time/` to all `<a href="{% url 'jira-ticket-detail' ... %}">` links
- `jira_integration/templates/jira_integration/ticket_detail.html`: render `<a href="{{ request.GET.back }}">← Back</a>` when `request.GET.back` is set (validate it starts with `/time/` to prevent open redirect)

## Acceptance Criteria

- Clicking a ticket from the time report and pressing Back returns to `/time/report/` with the same range active
- Clicking a ticket from the time entry list and pressing Back returns to `/time/`
- No regression in back navigation from other entry points to the jira detail page

## Validation Plan

- Navigate to `/time/report/?range=week`
- Click any ticket link
- Press browser Back — lands on `/time/report/?range=week`
- Navigate to `/time/`, click any ticket link
- Press browser Back — lands on `/time/`
- Navigate to `/jira/`, click a ticket, press Back — lands on `/jira/` (no regression)
