# v5.4.1 — Read-only Automation Tags in Settings Hub

## Goal

Tags that have been applied by the automation pipeline (source='automation') are Jira-owned and must not be editable or deletable from the Settings Hub frontend.

## In Scope

- Tags with any automation-sourced TicketTag → read-only in Settings Hub (no edit button, no delete button, lock icon shown)
- Tags with only manual usage or no usage → editable as before

## Out of Scope

- Changes to the ticket detail page (already correct)
- Changes to the automation pipeline or Jira integration
- Blocking edits via Django admin (admin is staff-only anyway)

## Technical Changes

- `settings_hub/views.py` — annotate `auto_count` (Count of ticket_tags with source='automation') on TagListView queryset
- `settings_hub/templates/settings_hub/tag_list.html` — hide edit/delete buttons when `tag.auto_count > 0`; show lock icon with tooltip

## Acceptance Criteria

- A tag applied by automation shows a lock icon and no edit/delete buttons in Settings Hub
- A tag applied only manually (or unused) shows edit/delete as before
- Hover tooltip on the lock explains it is Jira-managed
