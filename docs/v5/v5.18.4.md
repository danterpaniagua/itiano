# Goal

Move the **In Progress map** out of `/time/report/` into its own page, **`/time/map/`**, and give
it the new default view: a time-ordered **transition chain** under the **Exclusive** rule, one
card per stay (parents as envelopes), with a **Today | Week | Month | From → To** filter
(`dd/mmm/yyyy`) and an alert for subtasks that ran while their parent was not In Progress.

The current entries map (v5.18.0 / v5.18.1) stays available on the new page as the **Overlap**
view.

# Background

- The map today is a card inside `report.html` (1226 lines) that ignores the report's Time
  toggle and lists entries only. It cannot show tickets carried over from a previous day (e.g.
  GITIN-2315 and GITIN-2318 on Oct 30) or who really owned the time.
- Exclusive is now the report's default Time mode (v5.18.3): only one ticket owns time at any
  instant (latest entry wins, a parent yields to its active child, the previous ticket resumes
  when the owner leaves). A stay carried over from a previous day restarts at the first working
  hour of the day and counts nothing on a non-working day (v5.18.3).
- Approved layout: `docs/mockup/mockup_ip_map_cards.html` (local file, **real data**, never
  commit). `docs/mockup/mockup_ip_map_focus.html` is the discarded per-stretch variant.
- Real-week findings that shaped the rules: GITIN-2288 ran 9 stays under GITIN-2268, which stayed
  Blocked; GITIN-2318 ran evening stays while GITIN-2315 was not In Progress. Nothing in the
  report warned about it.

# Premise (rules)

1. **Route and access.** `GET /time/map/`, login required, the viewer's own tickets (same
   matching as the report: `jira_account_id`, legacy `jira_username` fallback). Linked from the
   Time Report header ("In Progress map"). The map card is removed from `report.html`.
2. **Range.** `?range=today|week|month|custom`, default `week`. Custom uses `date_from` and
   `date_to` typed as `dd/mmm/yyyy` (English month abbreviations, e.g. `23/Oct/2026`); ISO
   `yyyy-mm-dd` is also accepted. Same range windows and viewer timezone as the report. An
   invalid or reversed custom range shows an inline error and falls back to `week`.
3. **Two views.** `?time=exclusive` (default) or `overlap`. Overlap = the existing entries map,
   unchanged (entries, `x N`, origin and destination icons, Copy as Mermaid).
4. **Exclusive chain.** Per local day, newest day first. The chain is the slices each ticket owns,
   in time order, numbered `1, 2, 3...`, with a `Flow:` line of those numbers. Reuses the same
   ownership rule as the report (`_exclusive_ip_slices`) and the carry-over rule: a stay carried
   over from a previous day starts at the schedule's first working hour; a non-working day shows
   nothing for it.
5. **Cards.** One card per stay: ID (link to the ticket timeline, Jira link when
   `jira_base_url` is set), 2-line title, origin to destination icons, `start -> end`, owned
   time with the **Total | W-H** toggle (client-side), tags from `JiraTicket.labels` (3 + `+N`).
   Badges: `▶ since <date time>` on the first stay of a carried-over ticket, `↩ resumed` when the
   focus comes back, `⏸ paused` when another ticket took it, `running` when still open.
6. **Folding.** A return to a paused ticket shorter than 60 s is folded into that ticket's card
   with a note; its time still counts.
7. **Parent rules (per stay).**
   - A subtask stay while its **parent is also In Progress** sits in a **parent envelope** (parent
     ID and title, `parent in progress`, `1 of 2 subtasks`, the sum of its rows). Consecutive such
     stays of the same family share one envelope; when the family comes back later the envelope
     shows again marked `(continued)`.
   - A **parent owning the time alone** is a plain card.
   - A subtask stay while its **parent is not In Progress** is a plain card with
     `↳ subtask of X`; if the parent is the viewer's own ticket it also shows
     `⚠ parent not In Progress`. A parent that is not the viewer's gets no warning.
   - Parent state is evaluated at the start of the stay.
8. **Time is unchanged by any of the parent rules.** The subtask counts as the owner; a parent that
   was not In Progress gets nothing.
9. **Alert banner.** For the selected range: `N stays (time) ran under a parent that was not In
   Progress: <child> -> <parent> (count)...`, listing only stays whose parent is the viewer's own
   ticket. Hidden when there are none. Exclusive view only.
10. **Filters.** A tag filter (`?tags=`, AND) hides tickets that do not carry all the tags; it uses
    the clean Jira labels (`JiraTicket.labels`), the same tags the cards show, not `TicketTag`. It
    only hides: ownership and owned time are computed on all the viewer's tickets first. There is no
    status filter on the map.
11. **Numbers agree with the report.** For the same range, an Exclusive map's per-ticket owned time
    equals the report's Exclusive IP time for that ticket (All and W-H).

# In Scope

- `timetracking/focus_map.py` (new, pure functions, no DB access): builds the ordered stays from
  ticket segments, schedule and categories; applies rules 4, 6, 7, 8, and builds the alert data.
  The ownership sweep and carry-over rule are written once here for the map. (See Technical
  Changes for the duplication and how it is guarded.)
- `timetracking/views.py`: `TimeMapView` (data loading shared with the report where possible,
  range parsing for `dd/mmm/yyyy`), `urls.py` route `time/map/` named `timetracking-map`.
- `timetracking/templates/timetracking/map.html` (new) using the approved cards layout; reuse and
  move `_ip_map.html` for the Overlap view; remove the include from `report.html` and the
  `ip_map_*` context from `DailyReportView`; add the header link.
- Mobile-first (CLAUDE.md): action bar and filters `d-flex flex-wrap gap-2`, inputs `col-6`,
  cards stack full width, envelopes full width, no connectors on mobile, days with more than 4
  groups show 4 plus a "Show more / less" button, no horizontal scroll.
- Tests (see Validation Plan).
- Docs: new `.claude/feature_timetracking_map.md`; update `.claude/feature_timetracking_report.md`
  (the map section becomes a pointer); update `timetracking/templates/timetracking/docs.html`
  (In Progress map section for the new page and the Exclusive rules).

# Technical Changes

- New module `focus_map.py` and new view/template/route. No models, no migrations.
- `report.html` and `DailyReportView.get` lose the map include and its context keys; the
  `ip_map.py` module is kept (Overlap view).
- **Duplicated rule risk:** the Exclusive ownership sweep and the carry-over trim exist inside
  `DailyReportView.get` as closures. This scope implements them again as pure functions for the
  map rather than refactoring the report. The guard is a **parity test** (rule 11): the same
  fixture must give the same owned time on the map and in the report, wall-clock and W-H. v5.19.0
  removes the duplicate.

# Acceptance Criteria

- `/time/map/` renders the Exclusive chain for the Oct 30 real data as in the approved mockup: six
  stays in the order 2318 (in a 2315 envelope, `1 of 2 subtasks`), 2201 (`↳ subtask of 1310`, no
  warning), 2341, 2315 (plain card), 2341, 2343, with 2318 starting at 08:00 and `▶ since`.
- Today | Week | Month and From → To in `dd/mmm/yyyy` filter the days; an invalid range shows an
  error and does not crash.
- The alert shows the stays under a non-In-Progress parent of the viewer and is hidden when none.
- Carried-over tickets do not appear before the first working hour and do not appear at all on a
  non-working day.
- Owned time per ticket matches the report (parity test), All and W-H.
- The Overlap view equals the previous map (same entries and counts); `/time/report/` no longer
  renders the map and links to `/time/map/`.
- Anonymous users are redirected to login; a user without Jira link sees the existing link prompt.
- Works at mobile width without horizontal scroll.
