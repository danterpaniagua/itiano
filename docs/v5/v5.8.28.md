# v5.8.28 — In Progress Subtask Grouping (Visual)

## Goal

Visually group subtask tickets under their parent in the In Progress / Now panel and In Progress Timeline bar. No changes to time calculations.

## Context

When a user works on a subtask (a `JiraTicket` with a non-empty `parent_key`), the parent task should appear as a visual envelope wrapping the subtask card. This makes clear that the active work belongs to a larger task. The In Progress Timeline (single union bar) shows a bracket above the bar segments that belong to a subtask group.

---

## In Scope

### In Progress / Now panel

- If the active ticket has a `parent_key` that resolves to a known `JiraTicket`:
  - Render a parent envelope header (key + title, styled with blue border)
  - Render the subtask card inside the envelope
- If the active ticket has no `parent_key` (standalone): render as today — flat card, no envelope
- One subtask per parent envelope (by design — only one activity at a time)

### In Progress Timeline (single bar)

- Bar remains one single horizontal line — no extra rows
- If the active ticket has a `parent_key`: render a bracket above the bar spanning the IP segments, labeled with the parent key
- If standalone: bar renders with no bracket, as today

### Alert logic

- Current: alert fires when `len(today_rows) > 1`
- New: alert fires when number of **logical groups** > 1
  - A group = one envelope (parent + its subtask) OR one standalone ticket
  - Parent + subtask simultaneously active = 1 group, not 2 → no alert
  - Envelope + standalone simultaneously = 2 groups → alert fires

---

## Out of Scope

- Time calculation changes (no duration aggregation, no `range_seconds` changes)
- Gantt changes
- Status History changes
- Time by Status / Time by Tag changes
- Ticket timeline page (`/time/report/ticket/<key>/timeline/`)
- Multiple subtasks per parent in the panel (not needed — one activity at a time)
- Collapsible envelopes

---

## Technical Changes

- `timetracking/views.py` — `DailyReportView`:
  - Fetch `parent_key` for each IP ticket; resolve parent `JiraTicket` by `issue_key`
  - Pass parent info alongside each `today_row` for template rendering
  - Pass IP bar bracket data (parent key + segment positions) to timeline context
  - Update alert condition: count distinct logical groups instead of raw ticket count
- `timetracking/templates/` — In Progress / Now section:
  - Render envelope wrapper when `row.parent` is set
  - Render flat card when no parent
- `timetracking/templates/` — In Progress Timeline section:
  - Render bracket `<div>` above the bar track when parent group present
  - CSS: bracket styling (blue top border, key label)

---

## Acceptance Criteria

- Active subtask with a known parent → envelope rendered with parent key + title header
- Active standalone ticket → flat card, no envelope, identical to today
- Timeline bracket appears above bar when active ticket has a parent; absent for standalone
- Alert fires when envelope + standalone are both active simultaneously; does NOT fire when only parent + subtask are active together
- No change to any time duration value displayed anywhere
- Mobile layout remains usable
