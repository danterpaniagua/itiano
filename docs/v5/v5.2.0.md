# v5.2.0 — Tag Colors & Manual Ticket Tags

## Goal

Tags become first-class visual elements: each tag carries a color, automation-sourced tags are marked with 🤖, and users can add/remove colored tags directly on tickets without going through the admin.

## In Scope

### Model changes

- `Tag`: add `color` CharField(max_length=7, blank=True, default='') — stored as hex e.g. `#0d6efd`
- `Action.tag_expressions`: migrate from TextField (one line per expression) to JSONField storing
  `[{"expression": "$.issue.fields.labels[*]", "color": "#0d6efd"}, ...]`
  - Data migration: convert each non-blank line to `{"expression": line, "color": ""}` 

### Automation engine

- When resolving tag expressions, stamp `tag.color` from the expression config (create or update Tag).
- `TicketTag.source` is already `automation` for engine-created tags — no change needed.

### Action form

- Replace `tag_expressions` textarea with a dynamic row UI:
  - Each row: JSONPath input + Bootstrap palette swatches (primary/success/warning/danger/info/secondary) + hex text input with color preview span + remove button.
  - "Add expression" button appends a new row.
  - Serialised to hidden JSON input on submit.

### Ticket detail — tag management

- New inline tag section on `ticket_detail.html`:
  - Existing tags shown as colored pills: 🤖 prefix for `source='automation'`, plain for `source='manual'`.
  - "Add tag" control: text input with autocomplete from existing Tag names + color picker (same palette + hex as above) + Add button → POST to new `TicketTagAddView`.
  - Remove button per tag (staff or assignee only) → POST to new `TicketTagRemoveView`.

### Tag pill component

- Colored pill background from `tag.color` (fallback `#6c757d` if blank).
- 🤖 prefix when `ticket_tag.source == 'automation'`.
- Applied consistently in ticket list and ticket detail.

### New views & URLs (`/tickets/`)

- `POST /tickets/<pk>/tags/add/` — `TicketTagAddView`: creates or gets Tag(name, color), creates TicketTag(source=manual).
- `POST /tickets/<pk>/tags/<tag_pk>/remove/` — `TicketTagRemoveView`: deletes TicketTag.
- Both staff-or-assignee protected, return redirect or JSON (for AJAX if needed).

### Tag autocomplete endpoint

- `GET /tickets/tags/autocomplete/?q=<query>` — returns JSON list of `{name, color}` for matching tags.
  Staff only. Used by the "Add tag" input on ticket detail.

## Out of Scope

- Notification delivery (v5.3.0)
- Global tag management page (create/rename/delete tags globally)
- Tag filtering on ticket list (follow-up)
- Bulk tag operations

## Technical Changes

- `itsm/models.py` — `Tag.color` field + `display_color` property
- `itsm/migrations/` — AddField Tag.color
- `automations/models.py` — `tag_expressions` JSONField
- `automations/migrations/0008_action_tag_expressions_json.py` — three-step TEXT→JSONB migration using RunSQL
- `automations/dispatcher.py` — `_resolve_tags` and `_upsert_tags` updated for color stamping; `update_or_create` for TicketTag
- `automations/forms.py` — `tag_expressions` uses HiddenInput
- `automations/templates/automations/action_form.html` — dynamic tag expression rows
- `itsm/views.py` — TicketTagAddView, TicketTagRemoveView, TagAutocompleteView
- `itsm/urls.py` — three new URL patterns
- `itsm/templates/itsm/ticket_detail.html` — tag pills with color + 🤖 + add/remove UI
- `itsm/templates/itsm/ticket_list.html` — colored tag pills

## Acceptance Criteria

- Action form: tag expressions shown as rows with JSONPath + color picker; saved correctly as JSON.
- Automation engine: tags created from expressions carry the configured color; pills show 🤖.
- Ticket detail: staff can add an existing or new tag with color; remove any tag.
- Tag pills are colored in both ticket list and detail.
- Manual tags show no 🤖; automation tags always show 🤖.
- Hex input overrides palette selection when provided; they are mutually exclusive.
- Existing tag_expressions data is preserved through migration.

## Validation Plan

- Create Action with two tag expressions (different colors) → trigger via webhook → verify tags on ticket with correct colors and 🤖.
- Manually add a tag to a ticket → verify no 🤖, correct color, appears in list.
- Remove a tag from a ticket → verify removed.
- Existing action with old-format tag_expressions → verify migration preserved expressions.
- Non-staff user → verify add/remove returns 403.

## Migration Risk

- `AlterField` on `Action.tag_expressions` changes column type (TEXT → JSONB). Handled via RunSQL + USING cast. Run `SELECT COUNT(*) FROM automations_action` before applying in production.
