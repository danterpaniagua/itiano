# v5.8.20 — Ticket Timeline: Status History + Jira Link

## Goal

Make `/time/report/ticket/<key>/` answer the question "what's the situation with this ticket?" without requiring a date range selection. Add a full all-time status lifecycle and a direct link to Jira.

## Current State

- Ticket timeline page shows Time by Status, Manual Entries, Last Message, Messages, and Timeline — all range-filtered except Last Message.
- No current status badge in the header.
- No link to the Jira issue.
- No all-time status history — the date range gates everything.

## In Scope

### AppSetting model (`settings_hub`)
- New model: `AppSetting(key: CharField unique, value: CharField)`
- Migration: `settings_hub/migrations/0001_appsetting.py`
- Registered in `settings_hub/admin.py` for staff management.
- Helper: `get_app_setting(key, default='')` in `settings_hub/models.py`.
- Initial key: `jira_base_url` (e.g. `https://myorg.atlassian.net`). No trailing slash.

### Ticket timeline header
- Add current status badge (`JiraTicket.status`) next to the ticket key.
- Add Jira link button (`↗ Jira`) pointing to `{jira_base_url}/browse/{issue_key}`.
- Link only renders if `jira_base_url` AppSetting is set and non-empty.

### All-time Status History card
- New card above the date range picker.
- Shows the full status lifecycle of the ticket from first known event to now.
- Built from all `JiraEvent` records (same segment reconstruction as `DailyReportView`).
- Each segment: status name + duration. Current (open) segment shows `● now` and live duration.
- Displayed as a horizontal flow on desktop, stacked on mobile.

## Out of Scope
- Settings Hub frontend for `AppSetting` (admin only).
- Any `AppSetting` keys beyond `jira_base_url`.
- Editing ticket status from this page.

## Technical Changes

- `settings_hub/models.py` — `AppSetting` model + `get_app_setting` helper.
- `settings_hub/migrations/0001_appsetting.py`
- `settings_hub/admin.py` — register `AppSetting`.
- `timetracking/views.py` — `TicketTimelineView`: import `get_app_setting`, build all-time segments, pass `jira_url`, `all_time_segments`, `ticket_current_status` to template.
- `timetracking/templates/timetracking/ticket_timeline.html` — header badges + Jira link + All-time Status History card.

## Acceptance Criteria

- Staff sets `jira_base_url` in Django admin → Jira link appears on ticket timeline pages.
- All-time Status History shows every status the ticket has been in, with correct durations, regardless of the date range picker.
- Current status badge in header matches `JiraTicket.status`.
- If `jira_base_url` is not set, no link is shown and no error occurs.
- Mobile layout for All-time Status History is usable without horizontal scroll.
