# v5.8.33 — IP Bar: Range-Aware Ticks

## Goal

Fix the In Progress bar tick rendering for Week and Month ranges. Today remains unchanged. Multi-day ranges switch to daily ticks at work-start of labor days only (weekends skipped). Last zoom button label adapts to the active range.

## In Scope

- Add `range`, `whDayStarts` to `ip_bar_json` in the view
  - `range`: current range_param ('today', 'week', 'month', 'custom')
  - `whDayStarts`: UTC ms array of work-start timestamps for each labor day within [barStart, barEnd]
- JS tick logic update:
  - span ≤ 24h (today, 10h/WH zoom): existing hourly / 2h logic, unchanged
  - span > 24h: use `whDayStarts`, one tick per entry
- Tick label format:
  - span ≤ 24h: `HH:MM` (current)
  - span > 24h and ≤ 7 days (week): `Mon 30` (day abbr + day of month)
  - span > 7 days (month / long custom): `MM-dd`
- Last zoom button label: "Day" → "Week" / "Month" / "Range" based on `data.range`
- Today view: zero changes to behavior

## Out of Scope

- Changing tick behavior for 10h / WH-now / WH zoom modes
- Any Gantt or Status History changes
- Custom range UI

## Technical Changes

### `timetracking/views.py`
- Build `_wh_day_starts`: iterate bar_start → bar_end in user_tz, collect UTC ms of `schedule.start_time` for each active weekday. Empty list when no schedule.
- Add `'range': range_param` and `'whDayStarts': _wh_day_starts` to the `ip_bar_json` dict before serialization.

### `timetracking/templates/timetracking/report.html`
- Set last zoom button inner text from `data.range` on init
- Replace fixed `tickStep` logic with range-aware branch
- Add `fmtDayLbl` and `fmtMMDD` formatters
- Choose label style by span: ≤ 24h → 'hm', ≤ 7d → 'day', > 7d → 'date'

## Acceptance Criteria

- [ ] Today range: tick behavior unchanged
- [ ] Week range, Day→Week button: daily ticks Mon–Fri at work-start, labels "Mon 30" style
- [ ] Month range, Day→Month button: daily ticks at work-start, labels "06-30" style
- [ ] Weekends produce no tick
- [ ] 10h / WH-now / WH zoom on any range: still use hourly/2h ticks (span ≤ 24h)
- [ ] No schedule configured: whDayStarts empty, daily ticks fall back to midnight-based daily ticks with MM-dd labels

## Validation Plan

- Test Today range: verify ticks unchanged
- Test Week range Day (→Week) zoom: count ticks (should be 5 for Mon–Fri)
- Test Month range Day (→Month) zoom: count ticks (should match workday count in range)
- Switch to 10h zoom on week range: verify hourly ticks
- No schedule: verify graceful fallback
