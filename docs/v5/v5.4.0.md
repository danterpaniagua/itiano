# v5.4.0 — Settings Hub

## Goal

Staff-only frontend section to manage cross-app configuration (Tags and Categories) without requiring Django admin access.

## In Scope

- New `settings_hub` app
- **Tags**: list with name, color swatch, usage count; create; edit (name + color); delete blocked if tag is in use
- **Categories**: list with name and usage count; create; edit; delete (safe — SET_NULL on tickets)
- Staff-only access on all views
- Navbar entry (staff-only) linking to `/settings/`
- Dashboard card (staff-only)
- Docs section at `settings_hub/templates/settings_hub/docs.html`, included in `core/templates/core/docs.html`
- Mobile-first: responsive table + card fallback

## Out of Scope

- Ticket states, transitions, priorities (hardcoded domain logic)
- User management
- Jira, Vault, Automations configuration
- Role management

## Technical Changes

- `settings_hub/` — new Django app (models-free)
- `settings_hub/views.py` — TagListView, TagCreateView, TagEditView, TagDeleteView, CategoryListView, CategoryCreateView, CategoryEditView, CategoryDeleteView
- `settings_hub/urls.py`
- `settings_hub/templates/settings_hub/` — list and form templates
- `settings_hub/templates/settings_hub/docs.html`
- `config/settings.py` — add `settings_hub` to INSTALLED_APPS
- `config/urls.py` — mount at `/settings/`
- `core/templates/base.html` — staff-only navbar link
- `core/templates/core/dashboard.html` — staff-only card
- `core/templates/core/docs.html` — docs tab

## Acceptance Criteria

- Staff can list, create, edit, and delete Tags and Categories from `/settings/`.
- Deleting a Tag with active ticket associations is blocked with an error message.
- Non-staff users get 403 on all `/settings/` routes.
- Settings link visible in navbar for staff, hidden for non-staff.
- Dashboard card visible for staff only.
- Docs tab appears for staff in the central docs page.
- Mobile layout works without horizontal scrolling.
