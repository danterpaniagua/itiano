# Goal

Let a note **mention internal objects with `@`**: an ITSM ticket, a Jira ticket and a vault credential
(a link only, never the secret), with autocomplete as you type, and show on each of those objects
the **notes that mention it** (backlinks).

# Background

- Notes (`notes` app) are plain Markdown text (`Note.body`), edited with Write / Preview tabs (the
  preview is rendered in the browser with marked.js), owned per user and shareable read / write.
- Targets: ITSM ticket `ticket-detail` (`/<pk>/`, gated by `can_view_ticket`), Jira ticket
  `jira-ticket-detail` (`/<issue_key>/`, any logged-in user), credential `vault-detail` (new
  read-only page from v5.18.6, gated by `_can_access`).
- Sandbox notes (v5.18.5) will be full of JSON, so `@` also appears in emails and payload text; only
  strict tokens may become mentions.

# Premise (rules)

1. **Syntax in the body (source of truth).**
   - Jira ticket: `@GITIN-2315` (key pattern `[A-Z][A-Z0-9]+-\d+`).
   - ITSM ticket: `@ticket:42`.
   - Credential: `@cred:17`.
   A mention starts at a word boundary (so `user@host.com` is not one) and is ignored inside fenced
   code blocks and inline code. If an ITSM ticket and a Jira ticket share an external id,
   `@GITIN-2315` means the Jira ticket and `@ticket:<id>` the ITSM one.
2. **Autocomplete.** Typing `@` in the Write tab opens a list (works by touch): typing a Jira-key-like
   text suggests Jira tickets (`@GITIN-23...`), and a free text matches Jira titles, ITSM tickets
   (`@ticket:`) and credentials by name (`@cred:`). Minimum 2 characters, at most 8 results per kind,
   only objects the user can see; credentials show name and type only. Selecting inserts the token.
3. **Resolution at view time.** Labels and links are not stored in the body: the Preview tab sends the
   body to `POST /notes/mentions/resolve/`, which returns it with each mention replaced by a chip (one
   parser, same code rules): `GITIN-2315 · title`,
   `#42 · title`, `🔑 name`. A renamed object shows its new label.
4. **Per viewer, no leaks.** The resolver answers for the *viewer*: an object the viewer cannot open
   shows a placeholder (`credential (no access)`, `ticket (no access)`) with no name or title; a
   soft-deleted object shows `deleted`; an unknown id shows `not found`. A credential chip links to
   `vault-detail` and **never** returns a secret, ciphertext or notes.
5. **Backlinks.** `NoteMention(note, kind, ref)` is kept in step with the body on every save (parsed
   from the tokens, replaced as a set). The ITSM ticket page, the Jira ticket page and the credential
   page show **Notes mentioning this**: title and link of each note the viewer can read (owner or
   shared), nothing else; a note the viewer cannot read is not listed or counted.
6. **Cleanup.** Deleting a note deletes its mentions (cascade); a mention of a deleted object stays in
   the body and resolves as `deleted`.
7. **Sharing.** Sharing a note never shares the mentioned objects: each reader sees chips according
   to their own access.

# In Scope

- `notes/models.py`: `NoteMention` (+ one migration, new table only); `notes/mentions.py` (pure
  parser: tokens, boundaries, code fences) and resolver helpers.
- `notes/views.py`: mention search (`GET /notes/mentions/search/`) and resolve
  (`POST /notes/mentions/resolve/`) endpoints, mention sync in `NoteEditView.post`.
- `notes/templates/notes/note_edit.html`: autocomplete in the Write tab and chip rendering in Preview;
  mobile-first (full-width list, tappable rows).
- Backlink panels in the ITSM ticket detail, Jira ticket detail and vault credential detail templates.
- Tests in `notes`, `itsm`, `jira_integration`, `vault`; docs: `notes/templates/notes/docs.html`,
  `.claude/feature_notes.md` (create if missing) and the three target docs.

# Out of Scope

- Mentioning users, time entries or other objects; notifications when mentioned.
- Rendering mentions inside other apps' text fields, or a global "mentions" page.
- Saving mentions from the JSON Sandbox automatically (a follow-up of v5.18.5: a sandbox note opened
  from a Jira event could add `@KEY`).
- Any change to note sharing, encryption or the credential data.

# Technical Changes

- New table `NoteMention` (small; no lock risk). New parser module, two endpoints, template changes.

# Acceptance Criteria

- Typing `@GITIN-23` offers Jira tickets; `@ticket:` and `@cred:` offer ITSM tickets and credentials the
  user can see; the chosen token lands in the body.
- `user@host.com`, and `@` inside code blocks, are never mentions.
- Preview shows chips with the right label and link; a reader without access sees only the
  placeholder, never the name; a deleted object shows `deleted`.
- A credential chip links to the read-only page and exposes no secret in any response.
- Saving a note updates its mentions; the three object pages list only the notes the viewer can read.
- Works at mobile width without horizontal scroll.
