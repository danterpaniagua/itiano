# Goal

Add a **Save as note** action to the JSON Sandbox (`/sandbox/`) that stores the current work (payload,
JSONPath expression or automation filter, and the last result) as a note in the user's **Notes**
app, so useful queries and payloads are not lost when the page is left.

# Background

- The sandbox (`json_sandbox/views.py::sandbox`, staff only) evaluates a JSONPath expression or an
  automation filter against a pasted JSON payload. Nothing is saved: the form is posted and
  rendered back, and the payload survives only through the session handoff from other pages.
- The Notes app (`notes`) already has `Note(title, body, notebook, owner)` and
  `Notebook(name, owner)`, with per-note sharing. Notes are plain text (`body` TextField).
- Useful expressions and filters have been rebuilt by hand more than once (notification rules in
  v5.17.1, automations).

# Premise (rules)

1. **Action.** A **Save as note** button in the sandbox form, next to Evaluate / Test Filter. It
   posts the same form fields plus a `title` and creates a note owned by the current user.
2. **Content of the note.** Plain text with labelled sections, in this order, skipping empty ones:
   - `Mode:` jsonpath or filter
   - `Payload:` the JSON, in a fenced code block
   - `JSONPath:` the expression, or `Filter:` the filter JSON, in a fenced block
   - `Result:` the last result (JSONPath matches) or `Filter matched: yes/no`, when the form was
     evaluated
   The content is stored exactly as typed (not re-evaluated), so a note can hold an invalid or
   work-in-progress payload.
3. **Title and notebook.** The title is asked inline (default: `JSON sandbox - <date time>`). The
   note goes in a notebook named **JSON Sandbox** that is created for the user on first use
   (`get_or_create`). No notebook choice in this version.
4. **Access.** Same as the sandbox: staff only. The note belongs to the user; sharing and deleting
   use the existing Notes screens.
5. **After saving.** Redirect to the note (`note-edit`) with a success message that links back to the
   sandbox. The sandbox itself keeps working without saving.
6. **Size.** A payload over 1 MB is rejected with an error and nothing is saved.

# In Scope

- `json_sandbox/views.py`: a save branch in `sandbox` (or a small `save_as_note` view and URL) that
  builds the note body and creates the `Note` / `Notebook`; reuses `_check_staff`.
- `json_sandbox/templates/json_sandbox/sandbox.html`: the **Save as note** button and title field,
  mobile-first (action bar `d-flex flex-wrap gap-2`, full-width controls on mobile).
- Tests in `json_sandbox/tests.py` (see Validation Plan).
- Docs: `json_sandbox/templates/json_sandbox/docs.html` and a short mention in the Notes docs
  (`notes/templates/notes/docs.html`).

# Out of Scope

- Loading a note back into the sandbox ("Open from note"), a saved-queries list, versioning.
- Choosing a notebook, tags, or sharing at save time.
- Saving from other pages (automations, notification rules) and any change to `notes` models.
- New models or migrations.

# Technical Changes

- `json_sandbox` gains a dependency on `notes.models` (read and create only). No schema change, no
  migration, no new tables.

# Acceptance Criteria

- Staff users see **Save as note** and a saved note contains the sections above in order.
- The note is owned by the user, in the **JSON Sandbox** notebook, created if missing and reused on the
  next save.
- Non-staff users cannot reach the sandbox or save (403 as today).
- Saving without a title uses the default title; saving an empty form is rejected with a message.
- A JSONPath or filter that was evaluated stores its result; one that was not stores no result
  section.
- The button works at mobile width without horizontal scroll.
