# Goal

Add a **read-only credential page** to the vault (`/vault/<pk>/`) that shows a credential's metadata
and lets the user **copy each item** (URL, username, public key, certificate, and the secret fields)
without ever rendering a secret on the page. The secret is fetched only when a copy button is
pressed, kept only in browser memory for the moment it takes to copy, and the clipboard is cleared
after a configurable **TTL**. This page is the link target for credential mentions in Notes (v5.18.7).

# Background

- Today a credential can only be opened through the edit form (`vault-edit`) or copied from the
  list (`copySecret` in `credential_list.html`, POST `/vault/<pk>/copy/`, which decrypts per request
  and returns `{'secret': ...}`). There is no safe "just look at it" page to link to.
- Access rules already exist: `_can_access` (owner, legacy team member, any container grant),
  `_can_edit` (owner or read_write grant), soft-deleted credentials 404 (`is_deleted`). Secrets are
  encrypted per owner / container / team key; decryption must go through `decrypt_for_credential`
  (the shared resolver, see `feature_vault.md`), never a bespoke owner-first branch.
- Credential notes (`encrypted_notes`, `notes_shared`) have their own sharing toggle and are not part
  of this page.

# Premise (rules)

1. **Route and access.** `GET /vault/<int:pk>/`, name `vault-detail`, login required. Same gate as
   `credential_copy`: `_can_access`, soft-deleted credential 404, no access 403
   (`PermissionDenied`, like the other vault routes).
2. **What the page shows.** Name, type, owner, container path, visibility, tags, expiry date (with the
   existing "expiring soon" badge), URL (clickable and copyable), username (copyable), public key and
   certificate PEM (copyable, shown in a collapsed block). Secret fields (password, private key,
   passphrase / API secret) are **never rendered**, not even masked placeholders with length, only a
   **Copy** button per field that exists for the credential type
   (`CREDENTIAL_COPY_FIELDS`: password/secret `key`; API key `key` + `secret`; SSH key and certificate
   `key`).
3. **Copy flow.** Plain fields copy from the page. Secret fields call the existing
   `POST /vault/<pk>/copy/` (unchanged), write the value to the clipboard and drop the variable
   immediately; nothing is stored in the DOM, `localStorage`, `sessionStorage` or a cookie, and the
   response is not cached (`Cache-Control: no-store` on the copy response).
4. **TTL.** After a secret copy the page clears the clipboard after `vault_clipboard_ttl_seconds`
   (an `AppSetting`, default **30**, `0` disables), **one value for every user**, edited by staff at
   Settings -> App -> Vault (`/settings/vault/`), 0-3600. Clearing is best effort: it only overwrites the
   clipboard when it still holds the copied secret (read back where the browser allows it), so it
   never erases something the user copied later; if the page is hidden or the browser refuses, nothing
   happens. A small countdown next to the button shows the TTL. No server-side cache of decrypted
   values exists or is added (decryption stays per request).
5. **Actions.** An Edit button only when `_can_edit`; Back to the vault list.
6. **No audit log in this scope.** (Open decision: a copy audit entry, see below.)

# In Scope

- `vault/views.py`: `credential_detail` view (reuses `_can_access`, `_can_edit`), `Cache-Control:
  no-store` on `credential_copy`; `vault/urls.py`: `<int:pk>/` route.
- `vault/templates/vault/credential_detail.html` (new), mobile-first: cards stacked on mobile, copy
  buttons icon-only beside each row, action bar `d-flex flex-wrap gap-2`, no horizontal scroll;
  small inline script for copy and TTL.
- Link from the vault list to the new page (the credential name becomes a link; the edit icon stays).
- `AppSetting` key `vault_clipboard_ttl_seconds` read with `get_app_setting`; a small Clipboard card on
  `/settings/vault/` (staff) with its POST route `settings-vault-clipboard-ttl`.
- The vault list's existing `copySecret` buttons use the same shared script, so they get the same TTL
  (approved by the user: one rule in both places).
- Tests in `vault/tests.py` (new file; the vault had none); docs in `.claude/feature_vault.md` and `vault/templates/vault/docs.html`.

# Out of Scope

- Rendering or revealing secrets on the page, a "show for N seconds" toggle, credential notes.
- A copy audit trail, a per-user TTL, version history on the page, any change to encryption or sharing.
- New models or migrations; changes to `credential_copy` other than the cache header.

# Technical Changes

- One view, one route, one template, one header. No schema change.

# Acceptance Criteria

- A user with access sees the metadata and Copy buttons; the HTML never contains a secret, a masked
  value or a ciphertext.
- Without access: 403; soft-deleted or missing: 404; anonymous: redirect to login.
- Each copy button puts the right value on the clipboard and the secret is not stored client-side.
- With the TTL at 30 the clipboard is cleared after about 30 s only if it still holds the secret;
  `0` disables the clearing.
- Edit is shown only to users who can edit. Works at mobile width without horizontal scroll.
