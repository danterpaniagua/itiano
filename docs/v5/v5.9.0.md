# v5.9.0 — Time by Status: Trend, Oldest-Offender, Stuck Alert

## Goal

Add three of the four ideas from `.claude/deferred_time_by_status_enhancements.md` to the Time by Status card: a trend indicator vs. the previous equivalent range, an oldest-offender callout under Blocked/Testing/Backlog rows, and a card-level alert when a ticket is stuck beyond a configurable threshold. Priority-aware weighting is split out to a later scope (needs a new `JiraTicket.priority` field first — not yet modeled).

## Approved Mockup

- `docs/mockup/mockup_time_by_status_enhancements.html` — illustrates all three features together (plus the deferred priority badge, not built here)

## Decisions

| # | Question | Decision |
|---|---|---|
| 1 | Which rows get the trend indicator | Blocked/Testing/Backlog rows only (working-hours-scoped Sum from v5.8.36) — not In Progress. |
| 2 | Previous-range window | Equal-length window immediately preceding the current range: `today`→yesterday; `week`→prior 7 days; `month`→prior 30 days; `custom`→equal-length window before `date_from`. |
| 3 | Trend with zero previous value | Shows `new` instead of a percentage. |
| 4 | Oldest-offender scope | Blocked/Testing/Backlog rows only — ticket currently sitting in that status the longest (earliest ongoing `entered_at`). |
| 5 | "Working days stuck" unit | `working_seconds(entered_at, now) / per-day work window length`, rounded, minimum 1. |
| 6 | Stuck threshold config | Global `AppSetting` key `stuck_threshold_hours`, default 16. **Implemented at `/settings/time-report/`** (not `/settings/app/` as originally sketched — better fit alongside the other Time Report settings). |
| 7 | Which statuses trigger the stuck alert | Blocked and Testing categories only — not Backlog. |
| 8 | Alert visual | Reuses the multi-IP alert pattern (`border-warning`, `bg-warning text-dark`, count badge). |

## Implemented

### `settings_hub/views.py` + `time_report_settings.html`
- New `stuck_threshold_hours` `AppSetting` (default `16`), editable form at `/settings/time-report/`.

### `timetracking/views.py`
- Previous-range window calc (`prev_start_dt`/`prev_end_dt`).
- Trend `%`/`new` per Blocked/Testing/Backlog row.
- Oldest-offender lookup + working-days-stuck.
- Stuck-alert flag/count (`_status_stuck_alert`, `_stuck_count`) for Blocked/Testing tickets exceeding the threshold.

### `timetracking/templates/timetracking/report.html`
- Trend arrows, oldest-offender callout, warning header/badge on the Time by Status card.

## Follow-up fix delivered in this same scope: Done panel

During validation, user-reported count mismatches between the "Closed" card and the Time by Status closed footer led to two corrections, folded into this delivery:

1. **Closed card → renamed "Done"**, filtered to literal `Done` status only (excludes Descartado and any ticket that closed-then-reopened). Badge now uses `done_ticket_count` (individual ticket count), not `closed_groups|length` (which undercounted by collapsing parent/child groups).
2. **Time by Status closed footer** decoupled from the Done panel's data — it independently covers *all* terminal statuses (Done + Descartado), computed via its own loop rather than sharing `closed_tickets_raw`, so narrowing the Done panel didn't also strip Descartado from the footer.

## Out of Scope

- Priority-aware weighting (needs `JiraTicket.priority` field — separate future scope, tracked in `.claude/deferred_time_by_status_enhancements.md`).
- Trend/oldest-offender/stuck-alert on In Progress or closed-status footer.
- Per-user stuck threshold (single global setting).
