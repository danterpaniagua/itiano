# v5.8.30 — Closed Tickets Panel on Time Report

## Goal

Add a "Closed" panel (D) to the time report showing tickets that reached a terminal status within the selected range, grouped as envelopes (parent + subtasks) or flat standalones. Mirrors the In Progress panel's visual language.

## Visual Design

Left column stacks [A] In Progress and [D] Closed. [B] Time by Status and [C] Time by Tag remain full-height in the middle and right columns.

Closed panel row types:
- **Envelope**: green `border-success` border, green `#d1e7dd` header with parent key + title, subtask rows inside separated by `border-bottom`. Each subtask row: key (small muted) | closed-at (green) | IP time (muted) | title (bold below).
- **Standalone**: flat `border rounded` card. Same row layout as subtask.

## In Scope

- `closed_groups` computed in `DailyReportView`: tickets from `pivot_rows` whose terminal status `entered_at` falls within `[start_dt, now]`, grouped by `parent_key` (same pattern as `gantt_groups` / `pivot_groups`).
- Each entry carries: `ticket`, `closed_at` (tz-aware), `ip_time` (formatted IP seconds in range, or `None`).
- Sorted by `closed_at` descending within each group.
- Layout change: In Progress column becomes `d-flex flex-column gap-3` containing In Progress card + Closed card. `h-100` removed from In Progress card.
- Closed card: scrollable list (`max-height: 380px; overflow-y: auto`), count badge in header, empty state message when 0.

## Out of Scope

- Filtering closed list by tags or statuses.
- Showing parent ticket IP time (only subtask/standalone IP time shown).
- Tickets closed outside the range even if they had IP activity in range.
- Time by Status / Time by Tag changes.

## Technical Changes

- `timetracking/views.py` — `DailyReportView`:
  - After `pivot_groups`, compute `closed_tickets_raw` and `closed_groups`.
  - Add `'closed_groups': closed_groups` to context.
- `timetracking/templates/timetracking/report.html` — top row:
  - In Progress column: `col-12 col-md-4` → `col-12 col-md-4 d-flex flex-column gap-3`; remove `h-100` from In Progress card.
  - Add Closed card below In Progress within the same column.

## Acceptance Criteria

- Tickets whose terminal status `entered_at` is within the range appear in the Closed panel.
- Tickets closed outside the range do not appear even if they had IP activity in range.
- Parent envelope renders when one or more subtasks of a parent are closed in range.
- Standalone renders for tickets with no `parent_key` or whose parent has no closed subtasks in range.
- IP time shown per subtask/standalone; absent (`—`) when 0.
- Count badge in header matches the number of groups shown.
- Empty state shows when no tickets closed in range.
- In Progress and Time by Status/Tag panels are visually unchanged.
- Mobile layout stacks correctly.

## Validation Plan

- Load report on a range with known closed tickets: confirm panel appears with correct count.
- Verify envelope renders when a parent has closed subtasks.
- Verify standalone renders for tickets with no parent relationship.
- Load a range with no closed tickets: confirm empty state.
- Confirm tickets closed before the range do not appear.
- Confirm In Progress, Time by Status, Time by Tag are unaffected.

## Dependencies

- Reuses `pivot_rows`, `ticket_segments`, `ticket_seg_secs_map`, `_TERMINAL_STATUSES`, `_ip_statuses`, `user_tz`, `fmt` — all already present in `DailyReportView`.
