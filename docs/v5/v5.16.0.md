# Goal

Add a page-level **`Time: [ Overlap | Exclusive ]`** toggle to `/time/report/`. In
**Exclusive** mode only one ticket counts In Progress (IP) time at any instant, so the report
never shows more working time than elapsed time. `Overlap` (default) keeps today's behavior
unchanged.

# Background

Today every ticket's IP time is counted independently. When several of the user's tickets are
IP at once, the same wall-clock time is counted once per ticket.

Real data, 2026-10-01 (UTC, wall-clock), all assigned to the same user. `GITIN-2116` is a
child of `GITIN-2107`; `GITIN-2132` is standalone:

- `2107`: IP 00:00 → 09:31 (carried over), blocked, IP again 13:55 → now.
- `2116`: IP 13:55:02 → now (in Testing before that).
- `2132`: IP 10:07:37 → Done on Oct 2.
- From 13:55 all three are IP at once.

Current result for that day: envelope `2107+2116` = 19h36m, `2132` = 13h52m, total **33h28m** in
a 24h day.

# Premise (rules)

At any instant, with the user's IP tickets as candidates:

1. **Parent yields to its children.** Drop any ticket that has an IP child (`parent_key`
   match, child assigned to the same user). This runs before rule 2 and replaces any timestamp
   tie-break between a parent and its auto-transitioned child.
2. **Last in progress wins.** Among the remaining tickets, the one with the latest
   `entered_at` owns the time. Everyone else is paused (stack behavior).
3. **Resume.** When the owner leaves IP, the next most recent still-IP ticket owns the time
   again, and so on down the stack.
4. **Same-instant entries** (e.g. a bulk move): later `received_at` wins, then the higher issue
   key as a deterministic fallback.
5. **Only IP statuses** take part (`JiraStatusConfig` category `in_progress`). Blocked, Testing
   and other statuses are not made exclusive.

Expected result for the example day (acceptance numbers):

| Owner | Period | Time |
|---|---|---|
| 2107 | 00:00 → 09:31:14, plus 13:55:00 → 13:55:02 | 9h31m |
| idle | 09:31 → 10:07 | 36m |
| 2132 | 10:07:37 → 13:55:00 | 3h47m |
| 2116 | 13:55:02 → 24:00 | 10h04m |

Total 23h23m + 36m idle = 24h. The `2107+2116` envelope still totals 19h36m in the **Today
panel**, which counts every IP segment overlapping today.

Note: the report-wide panels (pivot, status totals, tag totals) keep the existing range rule that
only credits segments *entered* inside the range (plus ongoing ones). 2107's morning segment was
entered on Sep 30, so there it counts 0 in both modes and 2107 shows only its 13:55:00→13:55:02
slice (`0m`). Exclusivity does not change which segments qualify for the range.

# In Scope

- `timetracking/views.py`, `DailyReportView.get`:
  - Read a `time` GET param (`overlap` default, `exclusive`), validated like `range`.
  - Add a sweep over all IP segments of `my_tickets`, built on the **full history** (not
    range-clipped). Each ticket gets exclusive slices following rules 1-5.
  - Apply the existing range rule (`range_bounds`) and Labor clipping
    (`working_seconds_bounds`) to the slices. Exclusivity is computed first, clipping second.
  - In Exclusive mode, feed the slices into the IP-derived per-ticket totals: `ticket_seg_secs`,
    `ticket_range_secs`, and everything built from them (Time by Project, Time by Environment,
    tag totals, pivot IP column).
  - Today panel: `jira_today` and `jira_ongoing` use the exclusive slices. Paused tickets show
    `paused` instead of an ongoing duration. The envelope header total is the sum of the
    children's exclusive time plus the parent's exclusive time.
- `timetracking/templates/timetracking/report.html`: page-level `[ Overlap | Exclusive ]`
  `btn-group` in the header action bar (`d-flex flex-wrap gap-2`), preserved across range
  changes and the auto-update refresh. Small note under the header when Exclusive is on:
  "Exclusive: 1 task counts at a time".
- Tests in `timetracking` covering the rules and the real-data example above.
- Docs: update `.claude/feature_timetracking_report.md` after delivery, and the Time Report
  section in `timetracking/templates/timetracking/docs.html`.

# Out of Scope

- Making Blocked, Testing or any non-IP status exclusive.
- The IP bar and Gantt. They already show the union of IP periods and stay as they are.
- Tickets no longer assigned to the user (existing `my_tickets` limitation).
- Epic-level or deeper-than-one-level ancestry. `parent_key` is one level; a deeper chain is a
  follow-up.
- Correcting `received_at` skew versus the real Jira transition time (webhook delay).
- A side-by-side comparison card or a separate tab. A `deferred_*` file can be created if
  wanted.
- Changing `Overlap` mode in any way, including the v5.15.1 envelope rule.

# Known Conflict With v5.15.1

v5.15.1 sums concurrently IP **sibling** children with full, uncapped credit. In Exclusive mode
only one sibling counts at a time, so the exclusive rule wins. This applies **only** when the
toggle is on; Overlap keeps the v5.15.1 behavior exactly.

# Technical Changes

- `views.py`: local helper that builds the exclusive owner timeline from `ticket_segments`
  (sorted event sweep, O(n log n), one pass), plus the ancestor-suppression filter from
  rule 1. `ticket_seg_secs` selects overlap or exclusive slices based on the param.
- `report.html`: toggle markup and a hidden/query-preserving form param. No new JS framework;
  reuse the existing `env-mode-toggle` pattern.
- No model or migration changes.

# Acceptance Criteria

- Default (no param) output is identical to v5.15.1 for every panel.
- With `?time=exclusive`, the 2026-10-01 example gives 2116 = 10h04m, 2132 = 3h47m, 2107 = 0m
  in the report panels (range rule above); the Today panel envelope at 15:00 is 10h36m.
- Across any range, the sum of Exclusive IP time never exceeds elapsed time, and never exceeds
  elapsed working time with Labor on.
- A parent never receives time while one of its same-user children is IP, even when that child
  is preempted by an unrelated task.
- A preempted ticket resumes when the preempting ticket leaves IP.
- A pre-range preempting segment still preempts inside the range (exclusivity before clipping).
- A child in Blocked or Testing does not suppress its parent.
- The toggle works at mobile width without horizontal scroll and survives range changes and
  auto-update refreshes.
