# Goal

Add a way back to the previous page from the full `/notifications/` list — it had no navigation
out other than the browser's own back button.

# In Scope

- "Back" button in the page header, using `history.back()` rather than a link to a fixed parent
  page (same pattern already used by `json_sandbox/sandbox.html`) — appropriate here because
  `/notifications/` is reachable from several places (dashboard card, either bell dropdown's
  "View all"), so no single hardcoded destination is always correct.

# Out of Scope

- Any other notifications behavior — purely a navigation addition to one template.

# Technical Changes

- `notifications/templates/notifications/list.html`: `Back` button added to the header's
  `d-flex flex-wrap gap-2` action bar, before the title.
- `.claude/feature_notifications.md`: updated.

# Acceptance Criteria

- A "Back" button is visible on `/notifications/` and returns to whatever page the user was on
  before navigating there.

# Validation Plan

- `docker compose exec app python manage.py test notifications jira_integration vault
  settings_hub core` — **run, 59 tests, OK** (unchanged — template-only addition, no new
  behavior to unit test).
- Manual, via Django test `Client` against the real Postgres container: the button's markup
  (`history.back()`, "Back" label) is present in the rendered page.

# Related Scope Dependencies

- Depends on v5.13.0 (introduced the page this button is added to).
