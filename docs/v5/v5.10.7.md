# Goal

Restructure `/vault/`'s sidebar from a flat container tree into a Google-Drive-style owner-rooted tree: a **Personal** root (containers with no team `ContainerAccess` grant — `created_by`-only) and a **Shared** root grouped by Team (one sub-root per Team that has any `ContainerAccess` grant visible to the current user). Add a per-container **Share** shortcut that deep-links to that container's existing grant-management UI at `/settings/app/vault/` — no new inline grant UI, sharing stays settings-only and team-only, as confirmed with the user.

# In Scope

## Sidebar regrouping (`vault/views.py`, `vault/templates/vault/credential_list.html`)
- Partition `sidebar_containers` (currently one flat depth-first list, built in `credential_list`) into two groups:
  - **Personal**: containers where `created_by == request.user` AND the container has zero `ContainerAccess` grants from any team the user isn't the sole member of — in practice, simplest correct rule: a container is "Personal" for this user if it has **no `ContainerAccess` grants at all**. A container with any grant is "Shared", even if the current user is its `created_by`.
  - **Shared**: grouped by Team. For each `Container` with at least one `ContainerAccess` grant visible to the user (existing `accessible_containers` query already covers this), determine the set of Teams granting access, and place the container node under **every** team it's shared with (confirmed: multi-team overlap shows the container once per team, not collapsed to one).
- Existing parent/child ordering within each container is preserved (a shared child container appears under its team, indented under its parent if the parent is also visible under that same team; if the parent isn't shared with that team, the child is shown at top level under the team instead of orphaning the hierarchy).
- Existing per-node visible-credential counts (`visible_count`, computed against `_visible_credentials(user)`) are unchanged in meaning, just re-parented under the new grouping.
- The "All" and "Personal-pseudo-node" (uncategorized, `container=None`) links at the top of the sidebar are unchanged — this scope only restructures the *container tree* portion below them. Note: this pre-existing "Personal" link (for `container__isnull=True` credentials) and the new "Personal" **root group** (for personal *containers*) are two different things that both render the word "Personal" — see ASCII preview below for how they're visually distinguished.

## Share shortcut
- Each container node in the sidebar (Shared root only — a Personal container has nothing to share yet) gets a small share icon/link, staff-only (`{% if request.user.is_staff %}`), linking to `{% url 'settings-vault' %}#container-<pk>`.
- `settings_hub/templates/settings_hub/vault_settings.html`: add `id="container-{{ container.pk }}"` to each container's block (currently unanchored) so the deep-link lands on the right container.

# Out of Scope

- Any per-user direct-sharing primitive — confirmed team-only, existing `ContainerAccess`/`Team` model is sufficient (see Requirement Analysis Q&A).
- Inline grant creation/editing in `/vault/` — confirmed settings-only; the Share action only deep-links out, it does not open any grant form itself.
- Card-grid visual redesign, type icons, expiry badges — stays in `deferred_vault_visual_redesign.md`.
- Broadening `/settings/app/vault/` access beyond staff — the Share action is hidden from non-staff instead, per the confirmed decision, rather than changing who can reach that page.
- KDBX merge import — shifts to `v5.10.8`.

# Technical Changes

### `vault/views.py` — `credential_list`
- Replace the current flat `sidebar_containers` list with two structures passed to the template: `personal_containers` (flat or nested list, `ContainerAccess`-grant-free, `created_by`-scoped per the query already in place) and `shared_by_team` — a list of `(team, [container nodes...])` tuples, one entry per Team with a visible grant, each container's node list built with the same depth-first `.depth` annotation as today but scoped to containers shared with that specific team.
- A container with grants from two teams appears in two different `shared_by_team` entries (same `Container` object, evaluated fine since it's read-only per node in the template).

### `vault/templates/vault/credential_list.html`
- Sidebar card body restructured into two labeled sections (ASCII preview below). Existing `.vtree-link`/`.vtree-child`/`.vtree-count` CSS classes reused as-is; only the grouping markup changes, not the row styling.
- Share icon added inline on each Shared-root row, `{% if request.user.is_staff %}`.

### `settings_hub/templates/settings_hub/vault_settings.html`
- One-line addition: `id="container-{{ container.pk }}"` on the existing per-container block (around line 121, where `{% for container in containers %}` starts).

## Collapse/expand toggles (added mid-session, approved via the HTML mockup)

- A `−`/`+` toggle next to the **Shared** section label collapses/expands the entire Shared tree (all teams together) at once.
- Each **Team** sub-header (Operaciones, Dev, …) gets its own independent `−`/`+` toggle for just that team's containers.
- Each **Personal** top-level container that has children also gets its own `−`/`+` toggle for its children (e.g. "Azure" collapsing "CLOUD"/"SML").
- Implemented as one shared `.tree-collapse-toggle` JS binding (delegated per-button, toggles a `display:none` on a target id) reused for both the per-team and per-personal-parent cases; the master "Shared" toggle is a second, separate binding on `#sharedSection`.
- Required switching the sidebar from the old flat `.depth`-annotated list (`v5.10.6`'s deliberate choice to avoid template recursion for a simple indent-only list) to a real nested tree (`Container.node_children`, built in Python, rendered via a recursive `{% include %}` partial `vault/_container_tree_node.html`) — genuine collapsible nesting needs actual parent/child wrapping in the DOM, not just an indent class.
