# v5.8.9 — User Settings Page

## Goal

Create a dedicated `/settings/user/` page for per-user settings, clearly separated from app-level settings (Tags, Categories) that remain at `/settings/` (staff-only).

## Current State

- App settings (Tags, Categories) live at `/settings/` in `settings_hub`.
- User settings (Schedule, Timezone, Jira display name) live at `/time/schedule/` in `timetracking`.
- The schedule page sidebar incorrectly mixes staff app settings (Tags, Categories) with user settings (My Schedule).
- The v5.8.8 navbar dropdown links "Settings" to `/time/schedule/`.

## In Scope

- New URL `/settings/user/` in `settings_hub`, accessible to all authenticated users (no staff required).
- New view `UserSettingsView` in `settings_hub/views.py`.
- New template `settings_hub/templates/settings_hub/user_settings.html` with a left sidebar:
  - **My Schedule** — working days, start/end time (form, reuses `WorkSchedule` save logic)
  - **Jira display name** — jira_username field
  - **Timezone** — timezone field
  - **Contact channels** — list the user's own `ContactChannel` entries from their linked `Contact`; add/edit/delete inline. If no linked Contact exists, show a notice.
- Add `path('user/', views.UserSettingsView.as_view(), name='settings-user')` to `settings_hub/urls.py`.
- Remove Tags and Categories from the `timetracking/schedule_form.html` sidebar (they are app settings, not user settings). Keep `/time/schedule/` working as a redirect to `/settings/user/`.
- Update the v5.8.8 navbar dropdown "Settings" link from `timetracking-schedule` to `settings-user`.

## Out of Scope

- Password change
- Avatar / photo upload
- Editing or creating the linked Contact itself (only its channels)
- Any changes to Tags or Categories management

## Technical Changes

- `settings_hub/views.py`: add `UserSettingsView`
- `settings_hub/urls.py`: add `path('user/', ...)`
- `settings_hub/templates/settings_hub/user_settings.html`: new template
- `timetracking/views.py`: `WorkScheduleView` redirects to `/settings/user/` after save (or keep as-is and have `/settings/user/` call the same save logic)
- `timetracking/templates/timetracking/schedule_form.html`: remove Tags/Categories sidebar items; add redirect or deprecation notice
- `core/templates/base.html`: update dropdown Settings link to `{% url 'settings-user' %}`

## Acceptance Criteria

- `/settings/user/` loads for any authenticated user
- Page shows sidebar with My Schedule, Jira username, Timezone, Contact channels sections
- Schedule save works (same behavior as current `/time/schedule/`)
- Contact channels section lists existing channels; can add/edit/delete when linked Contact exists
- No Tags or Categories visible to non-staff on this page
- Navbar dropdown "Settings" goes to `/settings/user/`
- `/time/schedule/` redirects to `/settings/user/`

## Validation Plan

- Login as non-staff user → open dropdown → click Settings → lands on `/settings/user/`
- Edit schedule → save → changes persist
- Add a contact channel → appears in list
- Staff user → `/settings/` still shows Tags and Categories; `/settings/user/` shows user settings only

## Dependencies

- v5.8.8 (navbar dropdown) — must be merged first; this scope updates the Settings link target
- v5.8.7 (timezone field on WorkSchedule) — must be merged first; this scope surfaces that field in the new page
