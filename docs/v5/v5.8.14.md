# v5.8.14 — Multiselect Dropdown Filters for /jira/ and /tickets/

## Goal

Apply the same Bootstrap dropdown multiselect filter pattern introduced in v5.8.11 to the Jira ticket list (`/jira/`) and the ITSM ticket list (`/tickets/`). Both pages currently have limited or single-value filters; this brings them in line with the time report's UX.

## Current State

### `/jira/`
- Label filter via `GET.getlist('labels')` — existing multi-value backend, UI unknown (to verify before implementing).
- No status filter.

### `/tickets/`
- Single tag filter via `GET.get('tag')` — single-value only.
- Text search via `GET.get('q')`.
- No status filter.

## In Scope

### `/jira/` (`jira_integration`)

- Replace existing label filter UI with a **Labels** multiselect dropdown (Bootstrap dropdown with checkboxes, auto-submit on change).
- Add a **Status** multiselect dropdown filtering by `JiraTicket.status`.
- Active filter chips row with per-chip deselect (same pattern as v5.8.11).
- Clear-per-filter buttons.
- Filter state preserved across page interactions (hidden inputs).
- Available statuses collected from all non-deleted tickets.
- Mobile-friendly: dropdowns stack full-width.

### `/tickets/` (`itsm`)

- Replace single-tag `GET.get('tag')` with multi-tag `GET.getlist('tags')` in the view.
- Replace existing tag filter UI with a **Tags** multiselect dropdown.
- Add a **Status** multiselect dropdown filtering by `Ticket.status`.
- Active filter chips with per-chip deselect.
- Clear-per-filter buttons.
- Text search (`q`) preserved across filter changes (hidden input).
- Available statuses collected from existing tickets.
- Mobile-friendly.

## Out of Scope

- Assignee filter on either page.
- Changes to text search behavior.
- Pagination (carry filter params through pagination if it already exists; do not add pagination).
- Filter presets or saved searches.

## Technical Changes

- `jira_integration/views.py` — Jira list view: read `selected_statuses = GET.getlist('statuses')`; apply status filter; collect `all_statuses`; pass to template.
- `jira_integration/templates/jira_integration/ticket_list.html` (or equivalent): replace label filter UI, add status dropdown, add chips.
- `itsm/views.py` — ticket list view: change `GET.get('tag')` → `GET.getlist('tags')`; read `selected_statuses`; apply filters; collect `all_tags`, `all_statuses`; pass to template.
- `itsm/templates/itsm/ticket_list.html` (or equivalent): replace tag filter UI, add status dropdown, add chips.

## Acceptance Criteria

- `/jira/`: selecting one or more labels filters the list (AND logic, consistent with current behavior). Selecting one or more statuses further filters. Chips deselect individually.
- `/tickets/`: selecting one or more tags filters the list. Selecting one or more statuses filters. Text search still works alongside dropdowns. Chips deselect individually.
- Both pages: switching filters does not reset other active filters.
- Mobile: dropdowns are full-width and usable without horizontal scroll.
- No regression on existing label/tag filter behavior.

## Validation Plan

- Manual test on `/jira/` with labels + status combined.
- Manual test on `/tickets/` with tags + status + text search combined.
- Verify chip deselect on both pages.
- Verify mobile layout on narrow viewport.

## Dependencies

- v5.8.11 (filter pattern) ✅ Delivered — reuse same dropdown/chip HTML pattern.
- v5.8.13 — independent, can run in parallel or after.
