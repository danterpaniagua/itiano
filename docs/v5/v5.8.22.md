# v5.8.22 — Jira Account ID matching

## Goal

Replace display-name-based ticket matching with stable `accountId` matching.
Users pick their Jira identity from a dropdown in settings — it never breaks on display name changes.

## In Scope

- Add `jira_account_id` to `UserProfile` (identity field, not schedule)
- Add `assignee_account_id` to `JiraTicket`
- Backfill `assignee_account_id` on all existing tickets from stored `JiraEvent` payloads
- Update webhook parser to store `accountId`
- Timetracking views match on `assignee_account_id` via `UserProfile.jira_account_id`; fall back to `jira_username` if not set
- Settings UI: dropdown of known Jira accounts (displayName shown, accountId stored)
- App First/Last name is set in app settings, independent of Jira display name

## Out of Scope

- Removing `jira_username` from `WorkSchedule`
- Jira API calls

## Technical Changes

- `core/models.py` — add `jira_account_id` to `UserProfile`
- `core/migrations/0002_userprofile_jira_account_id.py`
- `jira_integration/models.py` — add `assignee_account_id`
- `jira_integration/migrations/0007_jiraticket_account_id.py` — schema + backfill data migration
- `jira_integration/views.py` — store `accountId` from webhook
- `timetracking/views.py` — match on `assignee_account_id` when set
- `settings_hub/views.py` — save `jira_account_id`, pass Jira accounts to context
- `settings_hub/templates/settings_hub/user_settings.html` — dropdown for Jira account

## Acceptance Criteria

- [ ] Webhook stores `accountId` on new tickets
- [ ] Existing tickets backfilled with `accountId` from event payloads
- [ ] User picks their Jira account from dropdown in settings
- [ ] Time shows correct tickets after selecting account
- [ ] Users without `jira_account_id` still matched via `jira_username` (no regression)
