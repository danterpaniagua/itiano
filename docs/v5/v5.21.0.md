# Goal

A **tag time report** at `/time/report/`: pick a Jira tag and get one row per ticket carrying it, with
its In Progress, Blocked and Paused time in working hours and its dates, plus a **Copy as prompt**
button that builds an AI prompt from a system prompt stored in Notes.

# Background

- v5.20.0 moved the current report to `/time/current/`, leaving `/time/report/` free (temporary redirects
  in `timetracking/urls.py` hold the old path until this scope).
- v5.19.0 added system prompts in Notes: `register(id, project, title, default)` and `get_prompt(id)`;
  this scope registers `prompt_time_report` (project folder `itiano`).
- Itiano status **Paused** = Jira **Blocked** time + **Overlapped** time (the ticket is In Progress but
  another ticket owns the focus under the Exclusive rule, the map's "paused" stays).
- The Exclusive engine already exists in `focus_map.py` (owned IP time, paused stays, carry-over rule,
  `working_seconds`); the range filter code is in `map_views.resolve_range`.

# Premise (rules)

1. **Route.** `GET /time/report/` (name `timetracking-report`), login required; the temporary redirects
   from v5.20.0 are removed. Own tickets only (assignee = the user's Jira account), like the map.
2. **Filters.** Same as the other time pages: **Today | Week | Month | From -> To** (dd/mmm/yyyy,
   `resolve_range`), default Week, plus a **tag** filter as chips + "+ tag" like the map (Jira labels of
   the user's tickets). With **no tag selected** the report uses the **main projects**: the tags in the
   `AppSetting` `time_report_default_tags` (staff-editable at Settings > Time Report; default
   `SmartPedidos, SmartLoyalty, Operaciones, SmartCloud`). A ticket is listed when its labels contain
   **any** selected tag. Rows are grouped by tag (one section per tag, with a subtotal); a ticket with
   two of the tags appears in both sections, and the grand total counts each ticket once.
3. **Table columns** (all time in working hours, `Xh Ym`): **ID** (link to Jira at
   `<jira_base_url>/browse/<KEY>`, plain text when the URL is not set), **Title**, **Jira tags**,
   **IP (WH)**, **Blocked (WH)**, **Paused (WH)**, **Created**, **Finished** (dd/mmm). Footer row with
   totals. No total-IP and no Overlap column.
4. **Time rules.**
   - IP (WH): time the ticket **owns** under Exclusive inside the range (same engine and carry-over rule
     as the map, so the numbers match `/time/map/`).
   - Blocked (WH): time in statuses whose `JiraStatusConfig` category is `blocked`, clipped to the range.
   - Paused (WH): Blocked + Overlapped, where Overlapped is IP time during which another ticket owned the
     focus. Paused is always >= Blocked.
   - Created: Jira `fields.created` from the stored events (fallback: the row's `created_at`).
     Finished: date of the last transition into a `done`-category status while the ticket is still done,
     otherwise "-".
5. **Prompt.** The template is the system prompt `prompt_time_report` (English, always), read with
   `get_prompt`; admins edit it in Notes > System Prompts. Placeholders: `{tag}` (the tags, comma separated), `{range}`, `{tickets}` (grouped by tag)
   (replaced as plain text, never `str.format`, so JSON braces are safe); if `{tickets}` is missing the
   block is appended. Built-in default (registered in code): act as an assistant summarising Jira work for
   the tag; for each ticket write a short description and a brief reason for each Blocked or Overlapped
   (Paused) period, using the ticket's "Qué pasó" section; say "reason unknown" when there is
   no evidence; answer in English.
6. **`{tickets}` block** per ticket: key, title, Jira tags, created / finished, IP / Blocked / Paused (WH), an
   **ASCII transition map** (status changes in the range with Blocked time, plus the Overlapped handoffs and who
   took the focus; added after review, the prompt needs it to explain the order of the pauses),
   the ticket's **"Qué pasó" section** and the paused periods (a first, simple version: no comments, no
   per-ticket tuning). "Qué pasó" lives in the ticket description as a Jira wiki-markup heading
   (`h2. Qué pasó`, bullets below, up to the next `hN.` heading or the end; matched without caring about
   accents or case). The description comes from the most recent stored event that carries one (about 40%
   of events do). When the section is missing the block says so and falls back to the first part of the
   description. Text is trimmed to a limit. The list of paused periods:
   Blocked ones (from, to, status, WH) and Overlapped ones (from, to, key + title of the ticket that took
   the focus, WH).
7. **Copy as prompt.** The button shows the full prompt in a read-only box (so it can always be selected)
   and copies it with a user click (works in Firefox). Nothing is sent to any service; the text can
   contain ticket content, so it is only copied.

# In Scope

- `timetracking/tag_report.py` (pure functions reusing `focus_map` for owned / paused time, blocked time,
  dates), a `TimeReportView` + template (table on desktop, cards on mobile) and the prompt endpoint.
- Register `prompt_time_report` in `notes/system_prompts.py` (or the timetracking app's `apps.ready`).
- `AppSetting` `time_report_default_tags` with a field on `/settings/time-report/`.
- Remove the temporary redirects; add the tag report button to the Current page header and a "Current"
  link on the new page; docs: `timetracking/templates/timetracking/docs.html`,
  `.claude/feature_timetracking_report.md` (new section), `feature_notes.md` pointer.
- Tests in `timetracking` (rules, parity with the map, filters, access, prompt text, placeholders).

# Out of Scope

- Sending the prompt to an LLM, multi-tag AND/OR, other users' tickets, export to files, editing tickets,
  the shared time-rules refactor (v5.22.0).

# Technical Changes

- New module, view, template and route; no migration. Description and "Qué pasó" text come from stored
  Jira event payloads (no new Jira calls).

# Acceptance Criteria

- With no tag the four main projects are listed, grouped by tag; choosing tags lists exactly the user's tickets with any of them; IP / Blocked / Paused match the map
  and the status config; Paused >= Blocked; dates are right; ID opens Jira.
- Same range filter as the other pages; works at mobile width without horizontal scroll.
- Copy as prompt shows and copies the English prompt with all tickets and their paused periods; an admin
  edit of the system prompt changes it; with the note missing the built-in default is used.
- `/time/report/` no longer redirects; `/time/current/` is unchanged.
