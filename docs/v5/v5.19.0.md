# Goal

Let Notes **persist system-wide prompts**: prompt templates that features (starting with the tag time
report) read by a stable id, kept as notes in a protected **System Prompts** folder that only some
roles can see and only admins can edit.

# Background

- Notes today: `Notebook(name, owner)` is flat and per user; `Note(title, body, notebook, owner,
  is_system)`; sharing per note (`NoteShare` read / write). `Note.is_system` already means a private
  scratch note, it is not reused here.
- The note edit route only allows owner or write-shared users (a read share gets 403, an existing gap).
- Next scopes use this: v5.20.0 renames `/time/report/` to `/time/current/`, v5.21.0 adds the tag time
  report at `/time/report/` and its **Copy as prompt** export, which reads `prompt_time_report`.

# Premise (rules)

1. **Folder tree with name + id.** Every system folder has a display `name` and an `id` (snake_case):
   ```
   System Prompts            id: system_prompts
   └─ Itiano                 id: itiano            (one folder per project)
      └─ Time report prompt  id: prompt_time_report (a note)
   ```
   The project folder is the project the prompt belongs to; today only `itiano` (system-wide prompts).
2. **Prompt ids.** `prompt_` + the feature's URL path in snake_case (`/time/report/` ->
   `prompt_time_report`). Format `^prompt_[a-z0-9]+(_[a-z0-9]+)*$`; unique across the system; the code
   finds a prompt by id, never by title. The id cannot be changed in the UI.
3. **Registry in code.** `notes/system_prompts.py` lists each prompt: id, project folder id, title,
   built-in default text. Features add their entry; v5.19.0 ships the mechanism with no feature prompt.
4. **Lazy creation.** The folders and the note are created from the built-in default the first time an
   admin opens System Prompts (or `ensure_prompt(id)` is called). `get_prompt(id)` returns the note body
   when it exists, otherwise the built-in default, so a feature never breaks if the note is missing.
5. **Placeholders.** The body is the template with `{name}` placeholders each feature documents
   (v5.21.0: `{tag}`, `{range}`, `{tickets}`). Unknown placeholders are left as typed; a feature that
   needs its data block appends it when its placeholder is missing.
6. **Who sees it.** The System Prompts folder is listed in the Notes sidebar only for: system admins
   (`is_staff`), users with the profile role `manager`, and users granted the dedicated permission (see
   open decision). Everyone else does not see it and gets 403 on its notes.
7. **Who edits it.** Only admins edit the body and title. Other allowed viewers get a **read-only**
   editor (no Save, no tabs to write). System prompts cannot be deleted, shared or moved from the UI.
8. **Personal notebooks are untouched** (still flat, per owner); system folders never appear in a user's
   personal list or in the notebook selector.
9. **Owner.** The note is owned by the admin who created it. Deleting that user deletes the note; the
   built-in default then takes over until an admin opens System Prompts again.

# In Scope

- `notes/models.py`: `Notebook.parent` (self FK, null), `Notebook.key` (blank), `Notebook.is_system`;
  `Note.key` (blank, unique when set), permission `view_system_prompts` on `Note`; schema migration with
  nullable / default columns, the personal-notebook unique rule becomes conditional (`is_system=False`) so
  a system folder never clashes with a personal one; data migration for the viewers group.
- `notes/system_prompts.py`: registry, `ensure_prompt`, `get_prompt`, `can_view_system_prompts`,
  `can_edit_system_prompts`, id validation.
- `notes/views.py` / `note_list.html`: System Prompts section in the sidebar (tree: folder, project,
  prompts); permission in the edit view for system notes (admin write, allowed roles read-only, others
  403); read-only editor mode (also used by a read-shared note, fixing its 403); hide delete / share /
  notebook controls for system notes.
- Tests in `notes`; docs: `notes/templates/notes/docs.html`, `.claude/feature_notes.md`.

# Out of Scope

- The time report prompt text and the report itself (v5.21.0); the `/time/current/` rename (v5.20.0).
- Per-user prompt overrides, prompt versioning or history, a "restore default" button, nested personal
  notebooks, admin UI to create arbitrary system folders (folders come from the registry only).

# Technical Changes

- Three nullable / defaulted columns on `Notebook`, one on `Note` (unique when non-empty), no table
  lock risk. New module, view permission branch, sidebar section.

# Acceptance Criteria

- An admin opens System Prompts and finds `System Prompts > Itiano > <prompt>` created from the
  registry default; edits and saves the body; `get_prompt(id)` returns the edited text.
- An allowed non-admin sees the folder and opens the prompt read-only; everyone else neither sees it
  nor opens it (403).
- A prompt id outside `prompt_*` snake_case is rejected; the id is not editable; a system note cannot be
  deleted or shared from the UI.
- With the note missing, `get_prompt(id)` returns the built-in default.
- Personal notebooks and personal notes behave exactly as before. Works at mobile width.

# Related Scope Dependencies

- Required by v5.21.0 (tag time report prompt). Independent of v5.20.0.
- Decided: view = system admin (`is_staff`) + profile role `manager` + a dedicated role created for the
  purpose; edit = system admin only.
- Decided: the dedicated role is the Django permission `notes.view_system_prompts` plus a "System
  Prompts viewers" group (created by a data migration), assigned in the admin and independent of
  `UserProfile.role` (which holds a single value). No new profile role.
