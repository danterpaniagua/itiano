**Delivered.**

## What Was Implemented

### 1. Gantt Timeline Panel (embedded in `/time/report/`)

Added below the Status History pivot table. Respects active tag and status filters.

#### View (`DailyReportView.get`)

- `gantt_rows`: for each ticket in `filtered_tickets`, builds a list of bars from `ticket_segments`. Each bar has `status`, `color`, `left` (% from range start), `width` (% of range), `ongoing`.
- **Terminal status suppression**: segments where `status` is in `{done, closed, cancelled, canceled, resolved, cerrado, terminado}` and `exited_at is None` are skipped — Done tickets stop at their last transition, not at "now".
- **Status filter applied to bars**: when `selected_statuses` is active, only bars matching those statuses are rendered (not just filtered at the ticket level).
- **Status color map**: fixed palette (`In Progress` → blue `#0d6efd`, `Bloqueado` → red `#dc3545`, `Done` → green `#198754`, `Backlog` → grey `#6c757d`, others → cycling fallback colors).
- `gantt_ticks`: X axis tick positions — every 2h for `today`, every 1 day for `week`, every 3 days for `month`.
- `gantt_legend`: unique status → color pairs from all rendered bars.
- **Working hour lines** (`work_lines`): two positions per working day (`start_time` and `end_time` from `WorkSchedule`), computed in the user's timezone. Only days enabled in `WorkSchedule` (mon–sun flags) produce lines. Lines within the range boundary only.

#### Template (`report.html`)

- Scrollable chart area (`overflow-x:auto`, `min-width:480px`).
- X axis tick labels above the chart, using `position:absolute` at `left:X%` of the tick row.
- Outer grid container with `position:relative` holding tick grid lines (1px `#e9ecef`).
- Per-ticket rows: 110px label column (ticket key link) + `flex-grow:1` bar track.
- Bar track: `position:relative`, `height:20px`, `background:#f8f9fa`, `border-radius:3px`, `overflow:visible`.
  - Status bars: `position:absolute`, `left:X%`, `width:X%`, colored, `opacity:0.9` (ongoing) or `0.75`.
  - **Working hour lines**: rendered inside each bar track at `left:{{ line.left }}%` with `top:-4px; bottom:-4px` (extends slightly beyond track for visibility). Uses `repeating-linear-gradient` for dashed effect (`rgba(25,135,84,0.9)`). `z-index:2` above bars.
- Color legend row below the chart.

### 2. Per-Ticket Activity Drill-Down (`/time/report/ticket/<key>/`)

New URL `report/ticket/<str:issue_key>/` → `TicketTimelineView`.

#### View (`TicketTimelineView.get`)

- Resolves `issue_key` → `JiraTicket` (404 if not found).
- Reads `date_from` / `date_to` from GET; defaults to today in user's timezone. Clamps `date_to >= date_from`.
- Converts date range to UTC `start_dt` / `end_dt` using `WorkSchedule.timezone`.
- Fetches all `JiraEvent` records for the ticket (all time) to build status segments for duration calculation.
- **All changelog items** within the range are shown — not just `field == 'status'`. Each changelog item becomes a timeline entry:
  - `type: 'transition'`: status change with `from_status`, `to_status`, duration in resulting status (clamped to range), `ongoing` flag.
  - `type: 'activity'`: any other field change — `field`, `from_val`, `to_val`.
- `TimeEntry` records for the ticket within the date range become `type: 'manual'` entries.
- Timeline sorted chronologically by `sort_key` (UTC received_at).
- Per-status totals computed from transition entries.
- `back_range`, `back_tags`, `back_statuses` read from GET and passed to template for back link reconstruction.

#### Template (`ticket_timeline.html`)

- Header with ticket key + back link to `/time/report/` with original params.
- Ticket title subtitle.
- Date range picker (from/to `<input type="date">`), hidden inputs carry back params.
- Summary: Time by Status card + Manual Entries total card.
- Desktop table (`.d-none.d-md-block`): columns When / Event / Duration·Detail.
  - Transition rows: `from → to` status badge, duration.
  - Activity rows: `table-secondary` style, field name + from → to values (truncated).
  - Manual rows: `table-light`, pencil icon, activity text, hours display.
- Mobile cards (`.d-md-none`): stacked layout per entry type.
- Empty state when no timeline entries.

## Verified

- Gantt renders with correct bar positions and colors.
- Terminal status (Done) bars stop at transition time, not at now.
- Status filter applies to Gantt bars (only selected statuses shown).
- Working hour lines appear at correct positions (work start/end per day in user's timezone) across all ticket rows.
- Lines invisible for users with no WorkSchedule; absent on non-working days.
- Drill-down shows all Jira changelog items + manual entries chronologically.
- Back link reconstructs report URL with original filters.
- 404 for unknown issue key; graceful empty state for no activity.
- Mobile layouts functional.
