# v5.8.19 — Credential Vault: Nested Folders

## Goal

Organize credentials into a KeePass-style nested folder tree. Users can create folders, nest them to any depth, and assign credentials to a folder. Navigation via a collapsible sidebar.

## Current State

- Credentials are a flat list with no grouping beyond tags.
- No folder or group concept exists in the model.

## In Scope

- New `CredentialFolder` model:
  - `owner` (FK User)
  - `name` (CharField)
  - `parent` (nullable self-FK for nesting)
  - `icon` (CharField, optional emoji or Bootstrap icon name, default `bi-folder`)
  - Unique constraint: `(owner, name, parent)`
- `Credential.folder` (nullable FK to `CredentialFolder`)
- Migration for both new model and new field.
- Credential list page gains a collapsible folder sidebar:
  - "All credentials" root view (no folder filter).
  - Click folder → filters list to credentials in that folder (and all descendants).
  - "Unfiled" virtual folder for credentials with `folder=None`.
- Folder management actions (inline or modal):
  - Create folder (under root or under a parent).
  - Rename folder.
  - Delete folder (only allowed if empty; or prompt to move contents).
- Moving a credential to a folder via the edit form (folder dropdown, scoped to user's folders).
- Mobile: folder sidebar collapses to a dropdown above the list.

## Out of Scope

- Sharing folders with teams (individual credential sharing still applies).
- Drag-and-drop reordering.
- Folder-level permissions.
- Visual redesign (v5.8.20).

## Technical Changes

- `vault/models.py` — `CredentialFolder` model + `Credential.folder` FK.
- `vault/migrations/0004_credentialfolder.py`
- `vault/views.py` — folder CRUD views + `credential_list` folder filter param.
- `vault/urls.py` — folder create/rename/delete endpoints.
- `vault/templates/vault/credential_list.html` — folder sidebar + folder param in filters.
- `vault/templates/vault/folder_*.html` (inline fragments or modals).
- `vault/forms.py` — `folder` field on `CredentialForm` (scoped to `owner=request.user`).

## Acceptance Criteria

- User can create a folder at root and a subfolder inside it.
- Credentials can be assigned to a folder via the edit form.
- Clicking a folder in the sidebar shows only credentials in that folder and its descendants.
- "Unfiled" shows credentials with no folder.
- Deleting a non-empty folder is blocked with a clear message.
- Folders not visible to other users (owner-scoped).
- Mobile sidebar collapses correctly.

## Dependencies

- v5.8.18 (search/sort/filter) — independent but recommend implementing first for a cleaner base.
