# Goal

When a week, a month or a custom N-day period closes, automatically save a **private personal note** with the
prompt the Time Report would have built for that period, and let staff choose which periods are created in
**Settings -> Time Report** ("Auto report creation": Weekly, Monthly, Other every N days).

# Background

- v5.21.0 builds the prompt (`tag_report.build_prompt`) from the default main-project tags in working hours.
- There is no scheduler in this stack: jobs are management commands run by host cron (`jira_reconcile`,
  `jira_rules_check`, see README). The generator follows the same pattern.
- Notes owned by a user are visible to that user only (no staff bypass); `Note.key` is global (system prompts),
  so personal files need their own id.
- Personal notebooks are flat today; `Notebook.parent` exists since v5.19.0 (system folders).

# Premise (rules)

1. **Settings section** at `/settings/time-report/` (staff), stored as `AppSetting` keys:
   - **Weekly** on/off (`time_report_auto_weekly`).
   - **Monthly** on/off (`time_report_auto_monthly`).
   - **Other**: on/off plus **every N days** (`time_report_auto_other`, `time_report_auto_other_days`, N >= 2) with
     an anchor date (`time_report_auto_other_anchor`, default the day it is enabled): periods run back to back
     from the anchor.
   - Default: Weekly and Monthly on, Other off.
2. **Command** `python manage.py time_report_close` (host cron, daily), idempotent. For every user with a Jira
   link it creates the notes of the periods that closed since the last run and are enabled; it never overwrites an
   existing note, so edits stay. Option `--backfill N` creates the last N closed periods per kind.
3. **Periods** (user timezone, `WorkSchedule.timezone`): month = calendar month, closes at its last midnight;
   week = Monday 00:00 to Sunday 23:59:59, belongs to the month of its Monday; other = N-day block from the anchor.
4. **Where and ids.** Personal folder **Personal / Jira Time Report / YYYY / MM** (nested notebooks; the year and
   month folders are named `2026` and `11` so alphabetical order is chronological; the month is the one of the
   period's start date, i.e. a week's Monday). File ids:
   month `YYYY-MM`, week `YYYY-MM_W<ISO week number>` (for example `2026-11_W45`), other `YYYY-MM-DD_<N>D`
   (start date of the block). Stored in a new `Note.file_id` (unique per notebook, blank for ordinary notes).
5. **Content**: the same text **Copy as prompt** gives for that period with the default tags (the
   `prompt_time_report` template as it is at creation time), frozen at close. Title: `Jira Time Report <id>`.
6. **Privacy**: owner only, never shared, not in anyone else's lists, backlinks or search; the owner can edit or
   delete it.
7. **Deleted notes** are not recreated (a small record of generated periods keeps track).
8. The settings page shows the cron line and the date of the last run.

# In Scope

- `Note.file_id`, nested personal notebooks in the sidebar, a generated-periods record, the settings section and
  its three actions, the management command, `timetracking/auto_reports.py` (period maths, pure), tests, docs
  (`feature_timetracking_tag_report.md`, `feature_settings_hub.md`, `feature_notes.md`, README cron line,
  in-app docs).

# Out of Scope

- Per-user opt-out or per-user tags, emailing or sending the prompt anywhere, regenerating an existing note,
  changing the prompt template, the time-rules refactor (v5.23.0).

# Technical Changes

- Migrations: `Note.file_id` (blank, conditional unique with the notebook), the personal-notebook uniqueness rule
  becomes per parent (the `MM` folders repeat every year), and a small table for generated periods. No lock risk on existing tables beyond the nullable-style column add.

# Acceptance Criteria

- Toggling Weekly / Monthly / Other in settings changes which periods the command creates.
- After a week or month closes the user finds `Personal / Jira Time Report / YYYY / MM / <id>` with the prompt; another user
  and staff cannot open it; running the command again changes nothing; a deleted note stays deleted.
