# v5.8.11 — Time Report: Filter Reorganization

## Status

**Delivered.**

## Goal

Replace the inline tag checkbox strip in `/time/report/` with organized multiselect dropdowns — one for Tags and one for Status. Improves usability when there are many tags or statuses, and adds the missing ability to filter the report by status.

## What Was Implemented

### `timetracking/views.py` — `DailyReportView.get`

- Added `selected_statuses = request.GET.getlist('statuses')`.
- Moved `all_statuses` computation earlier (before filtering), scoped to statuses with actual range activity only (segments with `secs > 0`). Previously computed from all-time segments regardless of range.
- Applied status filter after tag filter: keeps only tickets where at least one segment has a matching status and `secs > 0` in the range.
- Added `selected_statuses` to the template context.

### `timetracking/templates/timetracking/report.html`

- Removed the inline tag checkbox card.
- Added a filter bar card with two Bootstrap dropdowns (`data-bs-auto-close="outside"`):
  - **Tags** dropdown — checkboxes, auto-submit `tags-filter-form` on change; carries current `statuses` as hidden inputs.
  - **Status** dropdown — checkboxes, auto-submit `statuses-filter-form` on change; carries current `tags` as hidden inputs.
  - Active count badge on each button when filter is active.
- **Clear tags** / **Clear status** buttons: each clears only its own filter, preserving the other.
- Active filter chips row: each chip is a clickable `<a>` that deselects only that value (removes it from the URL while keeping all other active filters). Tag chips use `bg-primary`, status chips use `bg-secondary`. Each chip has a small `×` icon.
- Range toggle form updated to carry both `tags` and `statuses` as hidden inputs, preserving both filters across range changes.

## Out of Scope (confirmed not implemented)

- OR logic between filter values.
- Saving or naming filter presets.
- Filtering the "In Progress / Now" panel.

## Acceptance Criteria — Verified

- ✅ Tag filter reduces pivot rows correctly (5 → 2 for `tags=AWS`).
- ✅ Status filter reduces pivot rows correctly (5 → 4 for `statuses=In+Progress`).
- ✅ Combined tag + status filter applies AND logic (2 tickets for `tags=AWS&statuses=In+Progress`).
- ✅ Range toggle preserves both filters as hidden inputs.
- ✅ Clear tags keeps statuses; clear status keeps tags.
- ✅ Clicking a chip deselects only that value, keeping all others.
- ✅ In Progress / Now panel unaffected by filters.
- ✅ Filter bar hidden when no tags and no statuses available.
