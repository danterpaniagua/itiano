# Goal

Fix the notification bell being invisible on mobile: it lived inside the collapsible hamburger
menu, so it was only reachable by opening that menu first — not where a user expects to see a
notification indicator.

# In Scope

- Render the bell (icon + unread badge + dropdown) in two places: a compact instance next to the
  hamburger toggle button (visible below the `lg` breakpoint, outside the collapsible nav), and
  the original instance next to the avatar dropdown (visible at `lg` and above, where there's no
  hamburger to begin with).
- Extract the dropdown-menu content (notification list, "mark all read", "view all") into a
  shared include (`core/templates/core/_notifications_dropdown_menu.html`) so both instances stay
  in sync from one source.
- Add `text-light` to the bell's `<a>` for contrast against `navbar-dark bg-dark` (matches the
  avatar dropdown's existing styling) — a secondary, minor visibility fix reported alongside the
  main one.

# Out of Scope

- Any change to notification data/logic, `notify()`, or the settings pages — purely a navbar
  template/layout fix.
- A third bell placement for any other breakpoint — just the two Bootstrap already gives us via
  `navbar-expand-lg`.

# Technical Changes

- `core/templates/core/_notifications_dropdown_menu.html`: new, extracted from the existing
  single bell block.
- `core/templates/base.html`: brand / [mobile bell + toggler wrapped in one flex div] / collapse-div
  now sit as siblings in the navbar's `.container-fluid` (previously just brand / toggler /
  collapse-div) — the mobile bell is `d-lg-none`, the original desktop bell (now `d-none
  d-lg-block`) stays inside the collapse as before. Both include the shared partial rather than
  duplicating the `<ul class="dropdown-menu">` markup.

# Acceptance Criteria

- On a narrow viewport (below `lg`), the bell and its unread badge are visible next to the
  hamburger icon without opening the menu, and the dropdown opens/works from there.
- On `lg`+ viewports, the layout is unchanged from before this fix (bell next to the avatar
  dropdown).
- Both instances show identical, live data (unread count, recent list) since they share the same
  context-processor values and the same include.
