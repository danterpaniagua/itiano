# v5.8.36 — Time by Status Revamp: Working-Hours Calculation + Agent Self-Tracking

## Goal

Redesign the Time by Status card on `/time/report/` so it's useful for an agent tracking their own working time, and fix the underlying hour-miscalculation bug (e.g. `Done 983h 25m` in a 168h week range) using the `is_terminal` ("Closed Status") flag added in `v5.8.35`.

## Background

Root cause (confirmed in v5.8.35 scoping): a ticket's current status segment counts duration from `entered_at` to "now" with no exception for statuses the ticket never leaves. Separately, Bloqueado/Por Hacer (waiting statuses) accumulate raw wall-clock time including nights/weekends/holidays, which doesn't reflect real waiting effort during working hours.

## Decisions

| # | Question | Decision |
|---|---|---|
| 1 | Closed statuses (`is_terminal=True`, e.g. Done, Descartado) | Never shown as a duration bar. Shown as a single footer: total count of tickets closed this range + breakdown by status name + link to Closed Tickets panel. |
| 2 | Which non-terminal statuses can appear as bars | Any status whose `category` is `in_progress`, `blocked`, `testing`, or `backlog` — but a row only renders if it has time > 0 in the range. `other`-categorized statuses never appear on this card. |
| 3 | Row labels | Literal Jira status name (`seg['status']`), same as today — not the category label. |
| 4 | In Progress calculation | Raw calendar time (unchanged from today), **plus** a new `(Avg · N tickets)` annotation: `Avg = Sum ÷ distinct tickets that contributed`. This is the only row with the Avg combo. |
| 5 | Blocked / Testing / Backlog calculation | **Working-hours-scoped Sum only** (no Avg) — duration computed only for time inside the user's `WorkSchedule` window, not raw wall-clock. |
| 6 | `_TERMINAL_STATUSES` source | Switch from `category == 'done'` to `JiraStatusConfig.is_terminal == True` (both `DailyReportView` and `TicketTimelineView`). Fallback when no configs exist stays `{'done', 'descartado'}`. |
| 7 | Weekend/holiday-only blocked time | Contributes `0` — no special-case signal. |
| 8 | Default `WorkSchedule` | Mon–Fri, 09:00–18:00, `America/Argentina/Cordoba` for any user without one. `DailyReportView`/`TicketTimelineView` switch to `get_or_create(...)`. |
| 9 | Existing users' schedules | **Not retroactively changed.** Only the model field defaults change. |
| 10 | Bar sizing | `pct` relative to the max `secs` among the *shown* rows only. |

## Implemented

### `timetracking/models.py`
- `WorkSchedule.start_time` default `'08:00'` → `'09:00'`.
- `WorkSchedule.timezone` default `'UTC'` → `'America/Argentina/Cordoba'`.
- Migration `0006_alter_workschedule_start_time_and_more`: `AlterField` for both (state-only, no data migration).

### `timetracking/views.py`
- `DailyReportView`/`TicketTimelineView`: `WorkSchedule.objects.filter(...).first()` → `get_or_create(...)`.
- `_TERMINAL_STATUSES` derived from `is_terminal=True`.
- New `range_bounds`/`working_seconds`/`working_seconds_bounds` helpers (day-by-day, clipped to `WorkSchedule`).
- Restructured `status_totals`: In Progress (calendar Sum + Avg·N), Blocked/Testing/Backlog (working-hours Sum, hidden if zero), closed-status footer (count + breakdown by status, reused for the Done panel's data source before v5.9.0 decoupled them).

### `timetracking/templates/timetracking/report.html`
- Time by Status card restructured per approved mockup; `#closed-tickets-panel` anchor added to the Closed/Done card for the footer link.

## Out of Scope

- The four deferred enhancement ideas (moved to `v5.9.0` / `deferred_time_by_status_enhancements.md`).
- A general Working Hours Mode toggle across all report panels (remains `.claude/deferred_working_hours_mode.md`).
- Retroactively updating existing users' `WorkSchedule` rows.

## Acceptance Criteria

- [x] `/time/report/?range=week` no longer shows implausible Done/Descartado-driven totals — closed statuses show as a count + breakdown + link, never a duration bar.
- [x] In Progress row shows `Sum (Avg · N tickets)`; no other row shows Avg.
- [x] Blocked/Testing/Backlog rows show working-hours-scoped Sum only.
- [x] A row is hidden when it has no time in the range (verified: Testing hidden with no activity).
- [x] Any user without a `WorkSchedule` row gets one auto-created with the new defaults on first report view; existing configured schedules untouched.
- [x] Status History pivot, Time by Tag, Gantt unaffected.
- [x] Mobile-first: card layout matches existing responsive patterns.
