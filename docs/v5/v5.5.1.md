# v5.5.1 — Work Schedule

## Goal

Each user can configure their own working hours (days of week + start/end time). Used in future versions for working-hours calculations in time reports.

## In Scope

- `WorkSchedule` model on the `timetracking` app (OneToOne with User)
- Per-user schedule form at `/time/schedule/`
- Defaults: Mon–Fri, 08:00–18:00
- Link from the Time Tracking list page
- get_or_create on access so the form always shows something sensible

## Out of Scope

- Applying the schedule to report calculations (v5.5.2+)
- Manager visibility of other users' schedules
- Holiday calendars or exceptions

## Technical Changes

- `timetracking/models.py` — WorkSchedule model
- `timetracking/migrations/` — new migration
- `timetracking/views.py` — WorkScheduleView (GET/POST)
- `timetracking/urls.py` — path('schedule/', ...)
- `timetracking/templates/timetracking/schedule_form.html`
- `timetracking/templates/timetracking/entry_list.html` — link to schedule

## Acceptance Criteria

- User can open `/time/schedule/`, set working days and hours, and save.
- Revisiting the page shows the saved values.
- A user with no schedule sees the default values pre-filled.
- No user can view or edit another user's schedule.
