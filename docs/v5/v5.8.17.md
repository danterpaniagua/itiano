# v5.8.17 — Security: Vault & Notes Fixes

## Status

**Delivered.**

## What Was Fixed

### CRITICAL

**credential_copy — owner-only decryption** (`vault/views.py`)
Replaced `_can_access()` check with `credential.owner != request.user` guard. Team members can view credential metadata but cannot trigger decryption of another user's secret via the copy endpoint.

**Vault key derivation — PBKDF2 with per-user salt** (`vault/crypto.py`, `vault/models.py`, migration `0003`)
New vault keys are wrapped using PBKDF2-HMAC-SHA256 (260k iterations) with a 64-byte random per-user salt stored in `UserVaultKey.salt`. Existing keys (no salt) continue to use the legacy SHA-256 derivation for backward compatibility and are transparently handled on access.

### HIGH

**User enumeration in note share** (`notes/views.py`, `notes/templates/notes/note_share.html`)
`NoteShareView.get()` no longer returns all users. A minimum 2-character search query is required; results capped at 20. Template updated with a search input.

**Team queryset unrestricted in CredentialForm** (`vault/forms.py`)
`team` field now uses `Team.objects.filter(members=user)` instead of `Team.objects.all()`. Users can only assign credentials to teams they belong to.

### LOW

**System note delete bypass** (`notes/views.py`)
`NoteDeleteView` now raises `PermissionDenied` for system notes instead of redirecting with a flash message. Prevents bypass via direct POST.

## Known Deferred

Team credential shared-key encryption (allowing team members to legitimately decrypt team credentials) is tracked in `deferred_team_credentials_shared_key.md`. The current fix restricts decryption to owners only as an interim measure.

## Migration

`vault/migrations/0003_uservaultkey_salt.py` — adds `salt` CharField to `UserVaultKey`. Safe: nullable-equivalent default (`''`), no row rewrites.
