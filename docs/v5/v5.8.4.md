# v5.8.4 — Jira Parent/Child Issue Tree

## Goal

Show immediate parent and child (subtask) issues on the Jira ticket detail page and in the ITSM ticket detail Jira tab, using a `parent_key` field stored on `JiraTicket`.

## Current State

`JiraTicket` has no parent/child fields. Parent and subtask data arrives in webhook event payloads under `$.issue.fields.parent` and `$.issue.fields.subtasks` but is not persisted. The Jira ticket detail page and ITSM Jira tab display no relationship information.

## In Scope

- Add `parent_key = CharField(max_length=50, blank=True)` to `JiraTicket`
- Migration: schema migration + data migration to backfill `parent_key` from the latest event payload per ticket
- Webhook handler: populate `parent_key` when upserting a ticket from an incoming event
- `jira_integration/views.py` — `ticket_detail`: resolve parent `JiraTicket` (DB lookup by `parent_key`) and children (`JiraTicket.objects.filter(parent_key=issue_key)`); also extract children from latest payload for tickets not yet in DB
- Jira ticket detail template — "Related Issues" card:
  - Parent row: issue key (linked if in DB), summary, status, issue type
  - Children rows: same columns, one row per child
  - Card hidden if no parent and no children
- ITSM ticket detail Jira tab — append parent/child block below existing metadata
- `jira_integration/admin.py` — expose `parent_key`

## Out of Scope

- Multi-level tree (grandparents, grandchildren beyond immediate)
- Epic link type or other Jira link types
- Creating or editing relationships from the UI
- Children that have never sent a webhook event (payload-only children are shown as plain text, not linked)

## Technical Changes

- `jira_integration/models.py` — add `parent_key` field
- `jira_integration/migrations/0005_jiraticket_parent_key.py` — schema migration
- `jira_integration/migrations/0006_backfill_parent_key.py` — data migration reading latest event payload
- `jira_integration/views.py`:
  - In webhook upsert logic: extract `fields.parent.key` and write to `parent_key`
  - In `ticket_detail`: build `parent_ticket`, `children_in_db`, `children_payload_only` context vars
- `jira_integration/templates/jira_integration/ticket_detail.html` — Related Issues card above Event Log
- `itsm/templates/itsm/ticket_detail.html` — parent/child rows in `#panel-jira`
- `jira_integration/admin.py` — `parent_key` in `list_display` and `search_fields`

## Acceptance Criteria

- Jira detail page shows "Related Issues" card when a parent or children exist
- Parent row links to `/jira/<parent_key>/` if that ticket exists in DB, plain text otherwise
- Children rows link to `/jira/<child_key>/` if in DB, plain text otherwise
- ITSM Jira tab shows the same parent/child block for the linked Jira ticket
- Existing tickets without parent/child data show no Related Issues card (card hidden)
- Webhook for a child ticket updates its `parent_key` on arrival
- `parent_key` visible and searchable in Django admin

## Known Limitation

Tickets imported via bulk sync without webhook events will not be backfilled unless their latest stored event contains `fields.parent`. Operators can manually set `parent_key` via admin if needed.

## Validation Plan

- Open a Jira ticket known to have a parent — Related Issues card shows parent row
- Click parent link — navigates to parent ticket detail
- Open a parent ticket known to have subtasks — children rows appear
- Open a ticket with no relations — card is hidden
- Open ITSM ticket linked to a Jira ticket with parent — Jira tab shows parent row
- Check Django admin — `parent_key` column visible, search works
