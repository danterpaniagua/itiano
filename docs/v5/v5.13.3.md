# Goal

Let `jira_reconcile` notification recipients include more than one team — the v5.13.2 "Team"
field was a single-select dropdown; make it a checkbox list like Users, supporting any number of
teams at once.

# In Scope

- `jira_reconcile_notify_team` (single id) → `jira_reconcile_notify_teams` (comma-separated ids),
  same storage shape as `jira_reconcile_notify_users`.
- Settings UI: the single "Team" dropdown becomes a "Teams" checkbox list, visually and
  interactively matching "Users" directly above it.
- `_notify_completion()` resolves every current member of *any* checked team via one
  `User.objects.filter(vault_teams__pk__in=team_ids)` query, still deduped against the
  individually-configured users into a single `notify()` call.

# Out of Scope

- Anything about the Users checkbox list, the `notifications_enabled` toggle, or the
  `by_time`/`last` reconciliation logic — untouched.

# Technical Changes

- `settings_hub/views.py`: `JiraSettingsView._ctx()`'s `jira_reconcile_notify_team` (int or
  `None`) replaced with `jira_reconcile_notify_teams` (list of ints); `post()`'s
  `notify_users_form` branch now reads `request.POST.getlist(...)`, filters to digit-only and
  actually-existing team ids (silently dropping the rest, not erroring), and stores them
  comma-separated.
- `settings_hub/templates/settings_hub/jira_settings.html`: "Team" `<select>` → "Teams" checkbox
  list (same scrollable-box styling as Users).
- `jira_integration/management/commands/jira_reconcile.py`: `NOTIFY_TEAM_KEY` →
  `NOTIFY_TEAMS_KEY`; `_notify_completion()` reads the comma-separated list and queries members
  of any of them in one query; the now-unused `Team` model import removed (the query goes through
  `User.vault_teams`, not `Team` directly).
- `.claude/feature_notifications.md`: updated.

# Acceptance Criteria

- Checking multiple teams and saving persists all of them; reloading the page shows all as
  checked.
- Every current member of every checked team gets notified on the next `jira_reconcile`
  completion — no duplicates for a user in more than one checked team, and no duplicate for a
  user also individually checked in Users.
- A stale/invalid team id in a POST is silently dropped, not a crash.

# Validation Plan

- `docker compose exec app python manage.py test notifications jira_integration vault
  settings_hub core` — **run, 59 tests, OK** (up from 58: +1 multi-team test).
- Manual, via Django test `Client` against the real Postgres container: the Teams checkbox list
  renders, a two-team save round-trips both ids correctly, and a save with one invalid id among
  valid ones keeps only the valid one.

# Related Scope Dependencies

- Depends on v5.13.2 (introduced the single-team field this replaces).
