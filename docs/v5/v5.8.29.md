# v5.8.29 — Gantt Timeline Parent-Child Grouping (Visual)

## Goal

Visually group subtask tickets under their parent in the Gantt Timeline. No changes to time calculations.

## Visual Design

```
Timeline
──────────────────────────────────────────────────────────────────────
Ticket              │ 08:00    10:00    12:00    14:00    16:00
────────────────────┼─────────────────────────────────────────────────
GITIN-1824          │     [░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░]  ← parent own IP bar (lighter)
├ GITIN-1925        │          [████████]
├ GITIN-1936        │                    [██████]
└ GITIN-1954        │                              [████████████]
──────────────────────────────────────────────────────────────────────
GITIN-1111          │    [████████████]
──────────────────────────────────────────────────────────────────────

Legend:  ░ parent own IP bar (lighter color)   █ child / standalone IP bar
```

### Encoding rules

- **Parent row**: renders its own IP segments in a lighter color (e.g. `blue-200` / `opacity: 0.35`) to read as "context/container" rather than direct active work.
- **Child rows**: indented under the parent with tree prefix (`├` / `└`), render their own bars in the standard solid color.
- **No children with activity in range**: parent renders exactly as today — solid bar, no indent, no tree prefix.
- **Standalone ticket**: renders exactly as today — solid bar, no indent.

---

## In Scope

### Gantt Timeline

- Group `gantt_rows` by `parent_key`: parent row first, children rows immediately below with tree prefix.
- Parent bar: render parent's own IP segments at reduced opacity / lighter color.
- Child bars: render each child's own IP segments in standard color, label prefixed with `├` or `└`.
- Ticket label column: apply tree prefix (`├ ` / `└ `) for children; no prefix for parent or standalone.
- A visual separator (`─── `) divides parent groups from standalone rows and from each other.

### Fallback

- If a parent ticket has no children with bars in the current range → render the parent row exactly as a standalone (solid bar, no tree, no prefix).
- If a child has a `parent_key` but the parent has no bars of its own → child renders inside a group section but parent row shows no bar (label only, or omitted).

---

## Out of Scope

- Time calculation changes (no aggregation, no duration changes).
- In Progress / Now panel changes (covered by v5.8.28).
- In Progress Timeline bar changes.
- Time by Status / Time by Tag changes.
- Ticket timeline page (`/time/report/ticket/<key>/timeline/`).
- Collapsible groups.
- Parent row showing aggregate/union of children bars (separate idea, not scoped here).

---

## Technical Changes

- `timetracking/views.py` — `DailyReportView`:
  - After building `gantt_rows`, group by `parent_key` → `gantt_groups`.
  - After building `pivot_rows`, group by `parent_key` → `pivot_groups`.
  - Pass both grouped structures to template.
- `timetracking/templates/timetracking/report.html` — Gantt section:
  - Iterate `gantt_groups` instead of flat `gantt_rows`.
  - Render parent row with lighter bar CSS class.
  - Render child rows indented with left-border connector; omit work_lines inside child tracks (track is narrower, percentages would shift).
  - Render separator between groups and before standalone rows.
- `timetracking/templates/timetracking/report.html` — Status History section:
  - Iterate `pivot_groups` instead of flat `pivot_rows`.
  - Parent row: normal `<tr>`, no special styling.
  - Child rows: `border-left: 2px solid #a8c7fa` on `<tr>`, `padding-left: 1.5rem` on ticket `<td>`.
  - `border-top` separator before first standalone row.

---

## Acceptance Criteria

- Parent with IP children in range → parent bar at lighter opacity, children indented below with tree prefix.
- Parent with no children in range → renders as standalone (solid bar, no tree).
- Standalone ticket → identical to today.
- Status History: parent row renders normally; child rows have blue left border and indented ticket cell.
- Status History: standalone rows render identically to before.
- No change to any time duration value displayed anywhere.
- Mobile layout remains usable (tree prefix collapses gracefully on small screens).
