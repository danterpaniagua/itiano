# v5.8.27 — App Settings Hub

## Goal

Replace the flat `/settings/app/` page with a card-based hub. Each app gets its own dedicated settings page. Staff reach app config via the dashboard card, not the navbar.

## In Scope

### `/settings/app/` — hub page (staff only)
- Card grid: one card per app, linking to its dedicated settings page
- Initial cards: **Jira** (`/settings/jira/`) and **Tickets** (`/settings/tickets/`)
- Each card shows the app icon, name, short description, and a badge list of what's configurable
- Staff-only; non-staff users get a 403

### `/settings/jira/` — Jira app settings (staff only)
- Back link → `/settings/app/`
- **Base URL** (`#jira-base-url`): existing field + Save
- **Ticket Statuses** (`#jira-statuses`): existing table + inline add form

### `/settings/tickets/` — Tickets app settings (staff only)
- Back link → `/settings/app/`
- **Tags** (`#tags`): existing tag list + add/edit/delete
- **Categories** (`#categories`): existing category list + add/edit/delete

### Dashboard card
- Update existing Settings dashboard card to link to `/settings/app/`
- Card subtitle lists the available app sections (Jira, Tickets)

### Sidebar
- `_sidebar.html` updated: "App Settings" link → `/settings/app/`

### Profile page fixes (folded in)
- Full name: use `user.get_full_name()` as primary source, fall back to `contact.name`, then `—`
- Settings button: update link from `timetracking-schedule` → `settings-user`

## Out of Scope

- Adding new app settings sections beyond Jira and Tickets
- Moving any setting to a different app section
- User settings (delivered in v5.8.26)
- Any new models or permissions

## Technical Changes

- `config/urls.py`: add `settings/app/`, `settings/jira/`, `settings/tickets/` URLs
- `settings_hub/views.py`:
  - `AppSettingsHubView`: GET renders hub with card list
  - `JiraSettingsView`: replaces current `AppSettingsView` for Jira-related config
  - `TicketsSettingsView`: handles tags and categories
  - Existing tag/category/status add-delete URLs remain unchanged
- New templates:
  - `settings_hub/app_hub.html`
  - `settings_hub/jira_settings.html`
  - `settings_hub/tickets_settings.html`
- `core/templates/core/dashboard.html`: update Settings card link and subtitle
- `settings_hub/templates/settings_hub/_sidebar.html`: update App Settings link

## Acceptance Criteria

- `/settings/app/` shows hub with Jira and Tickets cards (staff only)
- Clicking Jira card navigates to `/settings/jira/` with Base URL and Ticket Statuses sections
- Clicking Tickets card navigates to `/settings/tickets/` with Tags and Categories sections
- Back link on each page returns to `/settings/app/`
- All existing add/edit/delete actions for tags, categories, and statuses continue to work
- Dashboard Settings card links to `/settings/app/`
- Non-staff users get 403 on all three pages
- Mobile layout on hub uses full-width stacked cards

## Validation Plan

- Log in as staff: navigate hub → Jira → add a status → delete it → back to hub
- Log in as staff: navigate hub → Tickets → create a tag → create a category → delete both
- Log in as non-staff: verify 403 on `/settings/app/`, `/settings/jira/`, `/settings/tickets/`
- Verify dashboard card links correctly
- Verify mobile layout on narrow viewport

## Dependencies

- Requires v5.8.26 to be delivered first (navbar cleanup, sidebar changes)
