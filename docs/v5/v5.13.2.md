# Goal

Fix the `jira_reconcile` notification-recipients UI (unusable native multi-select) and extend
recipients to also support an entire `core.Team`, not just individually-listed users.

# In Scope

- Replace the `<select multiple>` for `jira_reconcile_notify_users` with a checkbox list — the
  native multi-select required Ctrl/Cmd-click to select more than one option, which read as
  "can't add or remove" to a user clicking normally.
- New `jira_reconcile_notify_team` `AppSetting` (a `core.Team` id) — a dropdown alongside the
  user checkboxes. Every current member of the selected team is notified, combinable with the
  individually-checked users.
- Recipients from both sources are deduplicated into one recipient set before a single `notify()`
  call, so a user who is both individually configured and a team member gets one notification,
  not two.

# Out of Scope

- Multiple teams as recipients (one team dropdown only, as requested).
- Any change to the vault-share trigger, the `notifications_enabled` toggle, or the
  `by_time`/`last` reconciliation logic itself.

# Technical Changes

- `settings_hub/templates/settings_hub/jira_settings.html`: "Reconcile Notifications" section —
  checkbox list (same POSTed field name/shape, `getlist()` unchanged) + new team `<select>`.
- `settings_hub/views.py`: `JiraSettingsView._ctx()` adds `all_teams` and the currently-selected
  `jira_reconcile_notify_team` (as an int, or `None`); `post()`'s `notify_users_form` branch also
  saves the team id, clearing it (not erroring) if the posted id doesn't resolve to a real `Team`.
- `jira_integration/management/commands/jira_reconcile.py`: `NOTIFY_TEAM_KEY` constant;
  `_notify_completion()` resolves both sources into one deduped `set[User]` and makes a single
  `notify()` call; still a no-op when both sources are empty.
- `.claude/feature_notifications.md`: updated.

# Acceptance Criteria

- Clicking any checkbox in "Users" toggles just that user, independent of the others (no
  Ctrl/Cmd needed).
- Selecting a team in "Team" and saving notifies every current member of that team on the next
  `jira_reconcile` completion.
- A user both checked individually and a member of the selected team receives exactly one
  notification per run, not two.
- An invalid/stale team id posted to the settings form is silently cleared, not a crash.

# Validation Plan

- `docker compose exec app python manage.py test notifications jira_integration vault
  settings_hub core` — **run, 58 tests, OK** (up from 56: +2 team-recipient tests, including the
  dedup case).
- Manual, via Django test `Client` against the real Postgres container: settings page shows the
  checkbox list and team dropdown, a save round-trips correctly (checked/selected state persists
  on reload), and an invalid team id clears without error.

# Related Scope Dependencies

- Depends on v5.13.0/v5.13.1 (`notify()`, the notify-recipients settings section).
