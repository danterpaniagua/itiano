# v5.1.0 — Contacts

## Goal

A Contact model that enriches user identity with real name and multiple communication channels. Linked to ticket requesters — when a contact exists, the ticket displays "First Last" instead of the username.

## In Scope

### Models

- `Contact` — first_name, last_name, user (OneToOneField to User, null/blank), created_at
- `ContactChannel` — contact (FK), type (email | post | phone), label (optional), is_primary (bool)
  - `email` type: value = email address
  - `phone` type: value = phone number (display only)
  - `post` type: url, headers (JSONField key-value), body (TextField with template placeholders)

### Views and URLs (`/contacts/`)

- `ContactListView` — staff only, list all contacts
- `ContactDetailView` — view contact + channels
- `ContactCreateView` / `ContactEditView` — manage contact info + user link
- `ContactDeleteView` — staff only
- `ChannelCreateView` / `ChannelEditView` / `ChannelDeleteView` — manage channels per contact
- `ChannelTestView` — fires POST to the channel URL with editable fixture, returns status + response body inline (AJAX)

### Key-value header UI

POST channels show a dynamic add/remove row UI for headers (key + value inputs), stored as JSONField.

### Ticket display

- `itsm/templates/itsm/ticket_list.html` and `ticket_detail.html`: show `contact.first_name contact.last_name` when `requester.contact` exists, otherwise `requester.username`

### Dashboard card

- Contact count on `core/templates/core/dashboard.html` (staff only)

### Docs section

- `contacts/templates/contacts/docs.html` fragment
- Tab in `core/templates/core/docs.html` (staff only)

## Out of Scope

- Notification delivery (v5.2.0)
- Contact import / bulk create
- Public-facing contact form
- Contact search
- Org chart / manager relationships

## Acceptance Criteria

- Staff can create a Contact and link it to a User
- A Contact can exist without a User
- Each contact can have multiple channels of different types
- POST channel stores URL, headers (key-value), and body template
- Test button fires POST and shows status code + response body inline
- Ticket list and detail show contact full name when available
- Phone channel is display only (no send action)
- Dashboard card shows contact count (staff only)

## Validation Plan

- Create contact linked to a user → open a ticket by that user → verify full name shown
- Create contact without a user → verify it exists independently
- Add email, phone, post channels to a contact → verify all saved correctly
- POST channel: fill URL + headers + body → click Test → verify response shown
- Non-staff user: verify contacts routes return 403/redirect
