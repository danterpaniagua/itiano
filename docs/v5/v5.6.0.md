# v5.6.0 — Jira User Mapping + Active Ticket Panel

## Goal

Allow each user to configure their Jira display name so the Time Tracking list can surface
Jira tickets currently "In Progress" assigned to them — one tap to log time against an active ticket.

## In Scope

### Model changes

- `JiraTicket` — add `assignee` field (CharField, max_length=200, blank=True)
- `WorkSchedule` — add `jira_username` field (CharField, max_length=200, blank=True)

### Webhook handler

- Extract `fields.assignee.displayName` (Jira Cloud) from the incoming webhook payload and store it in `JiraTicket.assignee`

### Data migration

- Backfill `JiraTicket.assignee` from the most recent `JiraEvent.payload` per ticket
- Confirmed against production data: assignee values are `displayName` strings (e.g. "dantep", "Ruben Ferreyra")

### Time Entry list

- "My Active Jira Tickets" panel at the top of `/time/`
- Shown only when the user has `work_schedule.jira_username` configured
- Filters: `JiraTicket.status__iexact="In Progress"` AND `JiraTicket.assignee__iexact=jira_username`
- Each row shows: issue key, title, quick "Log time" button → `/time/new/?ticket=<issue_key>`
- If no active tickets: show a subtle note, not an error

### Work Schedule form

- Add `jira_username` field to `/time/schedule/`
- Label: "Jira display name" with help text explaining it must match the name shown in Jira

## Out of Scope

- Automatic time entry creation
- Filtering by any status other than "In Progress"
- Showing other users' active tickets
- Jira account ID / API-based lookup

## Technical Changes

- `jira_integration/models.py` — add `assignee` to `JiraTicket`
- `jira_integration/migrations/0003_jiraticket_assignee.py` — AddField + data backfill
- `jira_integration/views.py` — extract and store assignee in webhook handler
- `timetracking/models.py` — add `jira_username` to `WorkSchedule`
- `timetracking/migrations/0003_workschedule_jira_username.py` — AddField
- `timetracking/views.py` — pass active tickets to `TimeEntryListView`, save jira_username in WorkScheduleView
- `timetracking/templates/timetracking/entry_list.html` — active tickets panel
- `timetracking/templates/timetracking/schedule_form.html` — jira_username field

## Acceptance Criteria

- User sets "Jira display name" in `/time/schedule/` and saves.
- Webhook events received after this change populate `JiraTicket.assignee`.
- `/time/` shows a panel with tickets where status = "In Progress" and assignee matches.
- GITIN-1382 appears in the panel (backfilled from existing events).
- Quick "Log time" button pre-fills the ticket in the create form.
- Panel is hidden when no `jira_username` is set (prompt to configure shown instead).
- No panel shown when there are no matching active tickets (quiet empty state).

## Validation Plan

- Set jira_username in schedule form → verify it saves and persists.
- Verify GITIN-1382 appears in panel when jira_username = "dantep".
- Simulate webhook with different assignee → verify ticket does NOT appear in panel.
- Click "Log time" → verify form opens pre-filled with the correct ticket.
- Clear jira_username → verify panel is replaced with configuration prompt.
