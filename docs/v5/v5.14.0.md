# Goal

Capture Jira issue links (`blocks` / `is blocked by`) so a later scope can use them to roll a
linked Task's time into a linked Story, the same way a real subtask's time already rolls into its
parent. This scope is data-capture only — no Time Report behavior changes yet.

# In Scope

- New model `jira_integration.JiraIssueLink`: `ticket` (FK to the `JiraTicket` the link was read
  from), `linked_issue_key` (the other side, as a plain key — not a FK, since the other issue may
  not exist locally yet), `link_type` (`blocks` / `is_blocked_by`), `direction` implied by
  `link_type` itself (no separate field needed — Jira's API already returns the type from the
  perspective of the issue it's attached to).
- `jira_reconcile`'s per-issue fetch (`_fetch_issue_fields`, used by both `by_time`'s refresh path
  and `last`'s create path) requests `fields=...,issuelinks` and replaces each ticket's stored
  links with what Jira currently reports (full replace per sync, not incremental — links can be
  removed in Jira, and a diffing approach adds complexity for no real benefit at this data size).
  Only `blocks`/`is blocked by` link types are stored; any other link type (`relates to`,
  `duplicates`, `clones`, …) is fetched but discarded, matching the earlier decision that only
  these two matter for the rollup use case.
- Existing tickets get their links backfilled the next time they're touched by either verb
  (`by_time`'s normal refresh, or a `last` run covering their range) — no separate one-off backfill
  command, since `jira_reconcile last [N]` already exists for exactly this kind of gap-fill.

# Out of Scope

- Any Time Report rollup behavior (v5.14.1).
- Any other Jira link type.
- Writing links to Jira.
- Displaying links anywhere in the UI (ticket detail page, etc.) — purely backend data capture
  for now; a future scope if wanted.

# Technical Changes

- `jira_integration/models.py`: new `JiraIssueLink` model + migration.
- `jira_integration/management/commands/jira_reconcile.py`: `_fetch_issue_fields` requests
  `issuelinks`; `_reconcile_issue` (both the "existing ticket" and "create missing ticket"
  branches) replaces the ticket's `JiraIssueLink` rows from the fetched `issuelinks` data.

# Acceptance Criteria

- Running `jira_reconcile last 100` (or a `by_time` run) against real Jira for a range including
  `GITIN-1866`, `GITIN-1876`, `GITIN-1981` populates `JiraIssueLink` rows correctly reflecting
  their `blocks`/`is blocked by` relationships.
- A ticket with no qualifying links has zero `JiraIssueLink` rows, not an error.
- Re-running reconcile after a link is removed in Jira removes the corresponding local row (full
  replace, not accumulate-only).
