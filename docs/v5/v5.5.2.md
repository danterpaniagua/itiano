# v5.5.2 — Jira Status Duration

## Goal

Show how long each Jira ticket has spent in each status, derived from the webhook events already stored in jira_integration. No new model — computed on the fly.

## In Scope

- Parse `JiraEvent.payload.changelog.items` for status-change events (field == 'status')
- Build a status timeline per ticket: status, entered_at, exited_at, duration
- Display as a collapsible section on the Jira ticket detail page
- Duration formatted as: Xd Yh Zm for multi-day, Yh Zm for same-day, Zm for under 1h
- Current status shows elapsed time with an "ongoing" indicator

## Out of Scope

- Storing status durations in the database
- Aggregated reports across tickets
- Working-hours filtering (v5.5.1 schedule not applied here yet)

## Technical Changes

- `jira_integration/views.py` — compute status timeline in `ticket_detail`
- `jira_integration/templates/jira_integration/ticket_detail.html` — status history panel

## Acceptance Criteria

- Jira ticket detail shows a status history table with entered date, duration per status.
- Current status shows elapsed time as "ongoing".
- Tickets with no status-change events show no history panel (or a note).
- Duration is human-readable.
