# v5.8.26 — Merged User Settings Page

## Goal

Consolidate `/settings/user/` into a single `/settings/` page with independent, per-section save actions and proper anchor navigation. Remove the redundant staff navbar link to app settings.

## In Scope

### `/settings/` — merged user settings page
- New URL `settings/` replacing `settings/user/`; old URL redirects to it
- Sidebar becomes an anchor index: Personal Info, Schedule, Jira Account, Channels
- **Personal Info** (`#personal-info`): avatar + first/last name — own `<form>` + Save
- **Schedule & Work Hours** (`#schedule`): working days + start/end time + timezone — own `<form>` + Save
- **Jira Account** (`#jira-account`): dropdown extracted from schedule form — own `<form>` + Save
- **Contact Channels** (`#channels`): unchanged
- `UserSettingsView.post()`: add hidden `section=` discriminator (`personal`, `schedule`, `jira`) to dispatch partial saves correctly

### Navbar cleanup
- Remove the staff-only `⚙ Settings → /settings/app/` link from the top navbar
- User dropdown `Settings` link points to new `/settings/`

## Out of Scope

- App settings pages (scoped in v5.8.27)
- Dashboard card changes (scoped in v5.8.27)
- Contact Channels logic changes
- Any new models, URLs beyond the redirect, or permissions

## Technical Changes

- `config/urls.py`: add `settings/` URL; redirect `settings/user/` → `settings/`
- `settings_hub/views.py`: `UserSettingsView.post()` — section discriminator logic
- `settings_hub/templates/settings_hub/user_settings.html`: rewrite with 3 independent forms and anchor headings
- `settings_hub/templates/settings_hub/_sidebar.html`: anchor links instead of page links (for user context)
- `core/templates/base.html`: remove staff navbar `⚙ Settings` link

## Acceptance Criteria

- `/settings/` renders all four sections with correct anchors
- Saving Personal Info does not affect Schedule or Jira Account data and vice versa
- Saving Schedule validates timezone and start < end time as before
- User dropdown `Settings` navigates to `/settings/`
- Staff no longer see `⚙ Settings` in the top navbar
- Non-staff users see only the four user sections (no app config visible)
- `/settings/user/` redirects to `/settings/`
- Mobile layout remains fully usable

## Validation Plan

- Log in as non-staff: confirm only user sections visible, no app settings link in navbar
- Log in as staff: confirm no app settings link in navbar, user sections work
- Save each section independently and verify only that section's data changes
- Test timezone validation error still renders correctly
- Test avatar upload and removal
- Verify mobile layout on narrow viewport

## Dependencies

- None; this scope is self-contained
- v5.8.27 depends on this scope being delivered first
