# Goal

KeePass-style container tree navigation + search for `/vault/`, plus the ability to actually assign a credential to a container via the edit/create form (currently impossible — `container` isn't even a form field). Fixing that exposed a real, pre-existing bug shared with `visibility`/`team` reassignment, fixed in the same pass: **changing any field that determines a credential's encryption boundary (`container`, `visibility`, `team`) without also retyping the secret silently leaves the ciphertext encrypted under the old boundary** — this scope introduces one general re-encryption mechanism covering all of them, plus notes (which has its own, `notes_shared`-gated boundary that also depends on `container`).

# In Scope

## Navigation + search (`vault/views.py`, `vault/templates/vault/credential_list.html`)
- Container tree sidebar: recursive rendering of the `Container` hierarchy (parent/children), each node showing name + a count of visible credentials directly in it. A "Personal" pseudo-node for credentials with `container=None`. Clicking a node filters the list via `?container=<pk>` (or `?container=none` for the Personal node) — query-param based (not path-based), so it composes with the existing tag filter and new search, following the `itsm` ticket-list convention (hidden inputs round-trip other active filters).
- Search bar: `?q=<text>`, `icontains` across `name`, `username`, `url` (the only plaintext-searchable fields — `notes` is encrypted since `v5.10.3`, secrets always were). Same simple single-field-per-term pattern as the ticket list (no full-text search infra exists anywhere in this repo).
- Sidebar shows only containers the current user has *some* visible credential in, or has access to via `ContainerAccess` (any level) — not every container that exists globally.
- Existing table/mobile-card row rendering is otherwise **unchanged** — this is navigation/search, not the visual redesign (`deferred_vault_visual_redesign.md`, still deferred).

## Container assignment on the credential form (`vault/forms.py`)
- New `container` field on `CredentialForm` (`Meta.fields`), `ModelChoiceField`, queryset = containers where the user has `read_write` `ContainerAccess` or is `created_by`, plus the credential's current container if editing (always valid to keep the current value even if access lapsed — matters only in a real edge case since reaching the edit form at all already implies access).
- **General boundary-change re-encryption** in `CredentialForm.save()`: before `super().save(commit=False)` mutates the instance, capture the *old* `container_id`/`visibility`/`team_id` (and reuse the already-existing `_original_notes_shared`/`_original_notes` capture from `v5.10.3`). Compare against the submitted new values:
  - **Secret fields** (`encrypted_password`/`encrypted_private_key`/`encrypted_passphrase`): if `container`, `visibility`, or `team` changed *and* the user didn't type a fresh value for that specific field, decrypt it under the OLD boundary (using the instance's pre-mutation state) before the instance is mutated, then re-encrypt under the NEW boundary after. If the user *did* type a fresh value, it's encrypted directly under the new boundary as before — no old-ciphertext decrypt needed.
  - **Notes**: re-encrypt whenever `container_id` changes (notes boundary depends on `container_id` + `notes_shared`, independent of `visibility`/`team`) OR `notes_shared` changes OR the text itself changes — extends `v5.10.3`'s existing `text_changed or share_changed` check to `text_changed or share_changed or container_changed`.
- This fixes the *existing*, previously-unfixed bug for `visibility`/`team` reassignment (predates this scope, predates `v5.10.3` even) in the same pass, rather than three separate bespoke fixes.

# Technical Changes

### `vault/views.py` — `credential_list`
- New query params: `q` (search text), `container` (container pk, or the literal string `none` for the Personal/uncategorized node).
- `_visible_credentials(user)` unchanged; apply search/container filtering on top of it, same layering as the existing `tag` filter.
- Search: `credentials.filter(Q(name__icontains=q) | Q(username__icontains=q) | Q(url__icontains=q))` when `q` is present.
- Container filter: `credentials.filter(container_id=container_pk)` or `credentials.filter(container__isnull=True)` for `none`.
- New context: `sidebar_containers` — containers where `Container.objects.filter(Q(access_grants__team__members=user) | Q(created_by=user)).distinct()`, annotated/prefetched for tree rendering (parent chain) and per-node visible-credential counts (computed against `_visible_credentials(user)`, not a raw `.credentials.count()`, so counts reflect what *this user* can actually see, not the container's total).

### `vault/templates/vault/credential_list.html`
- New left sidebar column, `col-12 col-md-3` (**no** `d-none`/`d-md-none` anywhere — same breakpoint behavior as `notes/note_list.html`'s existing sidebar: full-width block that stacks *above* the credential list on mobile, sits beside it on desktop). Chip-strip mobile treatment (`deferred_vault_visual_redesign.md`'s original idea) was considered and rejected in favor of matching the existing Notes precedent exactly — see two local mockups compared 2026-07-12 (`docs/mockup/mockup_vault_option1_full.html` chosen over `mockup_vault_option2_full.html`).
- Recursive `{% include %}` partial (`vault/_container_tree.html`) rendering nested `<a>` nodes styled like `notes/note_list.html`'s notebook sidebar (`d-flex align-items-center gap-2`, active-state highlight, trailing count badge).
- Search input added to the existing filter bar (`card` > `card-body py-2` > `d-flex flex-wrap gap-2`), matching the ticket-list's `<input name="q">` + hidden-input round-tripping convention so it composes with the tag filter and container selection.

### `vault/forms.py` — `CredentialForm`
- Add `container` to `Meta.fields`. `__init__`: restrict `self.fields['container'].queryset` as described above; capture `self._original_container_id`, `self._original_visibility`, `self._original_team_id` (parallel to the existing `_original_notes`/`_original_notes_shared` capture).
- `save()`: restructured per the "General boundary-change re-encryption" design above — decrypt-under-old-boundary happens *before* `super().save(commit=False)` mutates the instance (that mutation is what makes `_resolve_credential_boundary` start reporting the *new* boundary), re-encrypt-under-new-boundary happens after.

### `vault/templates/vault/credential_form.html`
- New `container` field rendered near the existing `team`/`visibility` fields (simple `<select>`, matches existing field styling — no ASCII/HTML preview needed beyond what's already in this doc, single form field addition, not a structural change).

**Bug found and fixed during implementation** (pre-existing pattern, not introduced by this scope, but this is where it was caught): `CredentialForm.save()` originally read `self.instance.container_id`/`visibility`/`team_id` at the *start* of `save()` to detect a boundary change. But Django's `ModelForm._post_clean()` — called inside `is_valid()`, *before* `save()` ever runs — already mutates `self.instance` with the submitted values. So the "old" value read at the top of `save()` was actually already the *new* value, and boundary changes were never detected: a container/visibility/team reassignment silently left the secret encrypted under the old key. Fixed by capturing `_original_container_id`/`_original_visibility`/`_original_team_id`/`_original_owner` in `__init__` (before any binding/validation runs), mirroring the already-correct `_original_notes`/`_original_notes_shared` pattern from `v5.10.3`, and resolving the old encryption boundary from those captured values rather than from `self.instance` inside `save()`.
