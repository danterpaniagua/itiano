# v5.8.2 — Contact Channel Types: Hangouts, Jira, Telegram

## Goal

Add three new channel types to `ContactChannel` so contacts can store
Google Hangouts, Jira, and Telegram identifiers alongside email, phone, and POST.

## Current State

`ContactChannel.TYPES` has:
- `email` — text value (email address)
- `post` — URL field (webhook endpoint)
- `phone` — text value (phone number)

Template options and icon rendering are hardcoded to these three.

## In Scope

- Add `TYPE_HANGOUTS = 'hangouts'`, `TYPE_JIRA = 'jira'`, `TYPE_TELEGRAM = 'telegram'` to `ContactChannel`
- Migration (`AlterField` — choices only, no structural DB change)
- Add the three options to the type `<select>` in `channel_form.html`
- JS show/hide logic: all three new types use the `value` field (same as email/phone)
- Show appropriate icon per type on `contact_detail.html`:
  - hangouts → `bi-chat-dots`
  - jira → `bi-bug` (closest available)
  - telegram → `bi-telegram`
- `contacts/templates/contacts/docs.html` — mention new channel types

## Out of Scope

- Clickable links / deep links for the new types
- Validation of Jira username format
- Integration between `ContactChannel.jira` and `WorkSchedule.jira_username`

## Technical Changes

- `contacts/models.py` — three new type constants + TYPES list entries
- `contacts/migrations/0002_contactchannel_new_types.py` — AlterField migration (choices only)
- `contacts/templates/contacts/channel_form.html` — three new `<option>` tags; JS label map extended for new types; **pre-existing bug fixed**: replaced `{{ "{{" }}` / `{{ "}}" }}` with `{% templatetag openvariable %}` / `{% templatetag closevariable %}` — the original syntax caused a `TemplateSyntaxError` in Django 5.2 on every channel create/edit visit (zero channels had ever been created)
- `contacts/templates/contacts/contact_detail.html` — icon map for new types (desktop table + mobile cards)
- `contacts/templates/contacts/docs.html` — three new rows in channel types table

## Acceptance Criteria

- Channel form type dropdown shows Hangouts, Jira, Telegram options
- Selecting any new type shows the value field (text input)
- Saving and reopening preserves the type and value
- Contact detail page shows the correct icon for each new type
- Existing email/phone/post channels unaffected

## Validation Plan

- Create a contact, add a Hangouts channel — saves and displays correctly
- Add a Jira channel — saves and displays correctly
- Add a Telegram channel — saves and displays correctly
- Edit an existing email channel — unaffected
