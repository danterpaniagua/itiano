# v5.8.10 — Per-User Timezone: Range Filter + Display

## Goal

All datetimes in the app are stored in UTC. After v5.8.7 each user has `WorkSchedule.timezone` (IANA). This scope activates that timezone per request so that:
1. All rendered timestamps (creation times, event logs, report entries, etc.) are shown in the user's local time.
2. The Today / Week / Month range boundaries in `/time/report/` reflect the user's actual midnight, not UTC midnight.

## Current State

- `DailyReportView` computes `start_dt` as UTC midnight regardless of user timezone.
- All templates render datetimes as UTC (e.g. `{{ event.received_at|date:"d/m/Y H:i" }}`).
- `WorkSchedule.timezone` exists but is unused at render time.

## Approach

Django supports per-request timezone activation via `django.utils.timezone.activate(tz)`. When active, Django's template engine automatically converts aware datetimes to that timezone before rendering — no template changes required.

A single middleware class handles this for all views and templates.

## In Scope

- `core/middleware.py` — new `TimezoneMiddleware`:
  - For authenticated users with a `WorkSchedule`, call `timezone.activate(ZoneInfo(schedule.timezone))`.
  - For unauthenticated users or users without a schedule, call `timezone.deactivate()` (falls back to `settings.TIME_ZONE`).
- `config/settings.py` — add `TimezoneMiddleware` to `MIDDLEWARE` (after `AuthenticationMiddleware`).
- `timetracking/views.py` — `DailyReportView.get`: compute `start_dt` as midnight in the user's timezone (the activated timezone) instead of UTC midnight.

## Out of Scope

- Displaying a timezone label next to timestamps in templates (e.g. "14:30 COT") — deferred.
- Allowing users to set timezone from a different place than `/settings/user/`.
- Any changes to how datetimes are stored (always UTC).

## Technical Changes

- `core/middleware.py` — `TimezoneMiddleware` (new file)
- `config/settings.py` — `MIDDLEWARE` addition
- `timetracking/views.py` — `DailyReportView.get` range computation

## Acceptance Criteria

- User with timezone `America/Bogota` (UTC-5): all timestamps on all pages shown as local time, not UTC.
- User with timezone `UTC` or no schedule: no visible change.
- "Today" range in time report starts at 00:00 Bogota time for a Bogota user.
- Week and Month ranges respect the same boundary.
- Unauthenticated pages (login) unaffected.

## Dependencies

- v5.8.7 (timezone field on WorkSchedule) ✅ Delivered.
