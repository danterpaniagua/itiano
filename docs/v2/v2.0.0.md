# v2.0.0 – Jira Integration

## Goal

Receive Jira events via webhook, log incoming tickets and display their full change history. Update the dashboard with two sections: ITSM and Jira.

## In Scope

* `jira_integration` Django app
* `POST /jira/webhook/` endpoint — receives Jira webhook events
* `JiraTicket` model — one record per unique issue key (key, title, project, type, current status)
* `JiraEvent` model — one record per webhook event received (what changed, timestamp, raw payload)
* List view `/jira/` — one row per Jira ticket, latest status
* Detail view `/jira/<issue_key>/` — full event log for that ticket
* Dashboard updated with two cards: **Tickets** (ITSM) and **Jira**

## Out of Scope
* Integration between Jira tickets and ITSM tickets
* Outbound Jira API calls
* Terraform runner

## Technical Changes

* New `jira_integration` app with models, views, URLs, and templates
* `core/views.py` — dashboard updated with two sections
* `config/urls.py` — include `jira_integration` URLs
* `config/settings.py` — register `jira_integration` in `INSTALLED_APPS`, add `JIRA_WEBHOOK_SECRET`
* `HMAC-SHA256` signature validation on `X-Hub-Signature` header — rejects with 403 if invalid; skipped when secret is not set

## Acceptance Criteria

* `POST /jira/webhook/` receives a Jira event and returns 200
* Each unique issue key produces a single `JiraTicket` record
* Each received event produces a `JiraEvent` record linked to the ticket
* List view shows all Jira tickets with their latest status
* Detail view shows the full event log in chronological order
* Dashboard shows two cards: Tickets and Jira Integration

## Validation Plan

* Send a test `POST` to `/jira/webhook/` with a simulated Jira payload — verify 200 and record created
* Send two events for the same issue key — verify one `JiraTicket` and two `JiraEvent` records exist
* Verify list view on desktop and mobile
* Verify detail view shows events in chronological order
* Verify dashboard shows both cards
