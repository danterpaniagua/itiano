# v1.0.0 – Core Foundation

## Goal

Core foundation of the soft-ITIL ticket management platform.

## In Scope

* Django project with modular app structure
* PostgreSQL via Docker Compose (`app` + `db` services, persistent `logs/` and `data/`)
* User authentication (Django built-in, all views `@login_required`)
* `itsm` app: `Ticket`, `TicketEvent`, `Comment`, `Category` models
* Shared state machine (7 states) with transition enforcement layer
* Role-based permissions (Requester, Agent, Manager, Admin)
* Ticket views: create, list, detail, state transition actions
* Mobile-first UI (Bootstrap) per repository rules

## Out of Scope

* Email integration
* Jira integration
* Bot integration
* Azure Queue
* Reporting / dashboard

## Technical Changes

* New Django project (greenfield)
* `docker-compose.yml` with `app` and `db` services
* `Dockerfile` based on `python:3.12-slim`
* `itsm` Django app with models, transition layer, views, templates

## Acceptance Criteria

* `docker compose up` starts app and database with no errors
* Unauthenticated requests redirect to login
* Tickets can be created with type `Incident` or `Service Request`
* State transitions are enforced — invalid transitions return an error
* Each transition writes an immutable `TicketEvent` record
* Role permissions are enforced — unauthorized actions return 403
* All views are usable on mobile without horizontal scrolling

## Validation Plan

* Run `docker compose up` and verify both services start
* Log in and out as each role
* Create an Incident and a Service Request
* Walk the full state machine: `new → assigned → in_progress → resolved → closed`
* Attempt an invalid transition and confirm rejection
* Attempt an unauthorized action from a Requester account and confirm 403
* Verify ticket list and detail views on a mobile viewport

## Related Scope Dependencies

None — greenfield.
