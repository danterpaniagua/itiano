# v3.1.0 – Automations Frontend

## Goal

Human-facing, mobile-first frontend for the `automations` app. Allows staff users to list, create, edit, and toggle Triggers and Actions without accessing Django admin. Includes a read-only TriggerLog view for observability.

## In Scope

* **Actions**
  * List view `/automations/actions/` — name, type, system user, active state, trigger count
  * Create view `/automations/actions/new/`
  * Edit view `/automations/actions/<pk>/edit/`
  * Toggle active/inactive inline from list
* **Triggers**
  * List view `/automations/triggers/` — name, source, event type, linked action, active state
  * Create view `/automations/triggers/new/`
  * Edit view `/automations/triggers/<pk>/edit/`
  * Toggle active/inactive inline from list
* **TriggerLog**
  * List view `/automations/logs/` — trigger, action, result badge, timestamp; filterable by result and source
  * Read-only; no create or edit
* Navigation entry for Automations in `base.html` (staff-only)
* Dashboard card updated to link to `/automations/` instead of `/admin/automations/`
* All views restricted to `is_staff`
* Full mobile-first layout per CLAUDE.md rules: `table-responsive`, `d-md-none` card layout, `col-12 col-md-*` forms

## Out of Scope

* Visual filter builder (filter JSON entered as raw text in this version)
* Field mapping builder (field_mappings JSON entered as raw text)
* Pagination beyond basic Django paginator
* Trigger execution history per ticket
* Non-staff access to automations UI

## Technical Changes

* `automations/views.py` — class-based or function views for Actions, Triggers, TriggerLog
* `automations/forms.py` — `ActionForm`, `TriggerForm`
* `automations/urls.py` — URL patterns for all views
* `automations/templates/automations/` — list, form, and log templates
* `config/urls.py` — include `automations.urls`
* `core/templates/base.html` — Automations nav link (staff-only)
* `core/templates/core/dashboard.html` — update Automations card link to `/automations/`

## Acceptance Criteria

* A staff user can create, edit, and toggle an Action from the UI without using Django admin
* A staff user can create, edit, and toggle a Trigger from the UI without using Django admin
* TriggerLog list is accessible and filterable by result
* All pages render correctly on mobile without horizontal scrolling
* Non-staff users receive 403 on all `/automations/` URLs
* Dashboard Automations card links to `/automations/` not `/admin/automations/`

## Validation Plan

* Create an Action via UI — verify it appears in the list and in the database
* Edit the Action — verify changes saved
* Toggle inactive — verify `is_active` flips and trigger no longer fires
* Create a Trigger linked to the Action — verify it appears in the list
* Send a matching Jira webhook — verify TriggerLog entry appears in log view
* Resize browser to mobile width — verify no horizontal scroll on any page
* Access `/automations/` as non-staff — verify 403

## Related Scope Dependencies

* v3.0.0 — `automations` app, models, engine, Django admin
