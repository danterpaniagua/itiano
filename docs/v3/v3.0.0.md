# v3.0.0 – Automations Engine

## Goal

New `automations` Django app providing a configurable rule-based engine. **Triggers** (integration source + structured JSONPath filter conditions) fire **Actions** (ticket creation with JSONPath field mappings). Configured via Django admin.

## In Scope

* New `automations` app registered in `INSTALLED_APPS`
* `Action` model — `action_type`, `field_mappings` (JSONField), `system_user` (FK to User), `is_active` flag
* `Trigger` model — `source`, `event_type`, `filter` (JSONField), `is_active` flag, FK to `Action`
* Structured JSON filter evaluator — operators: `and`, `or`, `eq`, `neq`, `in`, `not_in`; missing JSONPath → silent non-match (logged as DEBUG)
* JSONPath resolver — evaluates `$.path` expressions against raw payloads using `jsonpath-ng` (already in `requirements.txt`)
* Action type `create_ticket` — maps field_mappings to existing `Ticket` fields only (`title`, `description`, `type`, `priority`, `category`)
* `system_user` on `Action` resolves the required non-nullable `Ticket.requester` FK
* Dispatch hook in `jira_integration/views.py` — one call after `JiraEvent.objects.create()`
* Django admin for `Action` and `Trigger` — create, edit, enable/disable, filter by source
* `TriggerLog` model — one record per dispatch: trigger, action, payload snapshot, result (`matched` / `skipped` / `error`), timestamp

## Out of Scope

* Dedicated frontend pages for Trigger/Action configuration (admin-only in this version)
* New `Ticket` fields: `service`, `sub_service`, `tags` — deferred to v3.1.0
* Action mappings for `service`, `sub_service`, `tags` fields
* Other action types: email notification, outbound webhook, Jira comment
* Other integration sources: `email_integration`, `bot_integration`
* Async/queue execution of actions
* String DSL parser for filters

## Technical Changes

* New `automations/` app: `models.py`, `evaluator.py`, `resolver.py`, `dispatcher.py`, `admin.py`, `apps.py`, `migrations/`
* `jira_integration/views.py` — +1 `dispatch()` call at end of `webhook()` view
* `config/settings.py` — register `automations` in `INSTALLED_APPS`
* `config/urls.py` — no URL changes (admin auto-registered)

## Acceptance Criteria

* An `Action` with `action_type=create_ticket` can be created in Django admin with a valid `system_user` and `field_mappings` JSON
* A `Trigger` can be created linked to an `Action` with a `source`, `event_type`, and `filter` JSON
* Sending a Jira webhook payload that matches the Trigger filter creates an ITSM `Ticket` with fields resolved from the payload
* Sending a payload that does not match the filter creates no ITSM ticket
* A `TriggerLog` record is written for every dispatch attempt (matched, skipped, or error)
* An inactive Trigger (`is_active=False`) is never evaluated
* An inactive Action (`is_active=False`) is never executed
* Missing JSONPath in payload does not raise an exception — Trigger is skipped

## Validation Plan

* In Django admin: create an `Action` (create_ticket) and a `Trigger` with filter `{"and": [{"path": "$.issue.fields.project.name", "op": "eq", "value": "GIT - Infraestructura"}]}`
* Send a webhook payload where `$.issue.fields.project.name == "GIT - Infraestructura"` — verify `Ticket` created and `TriggerLog` shows `matched`
* Send a payload where `$.issue.fields.project.name == "OTHER"` — verify no Ticket created and `TriggerLog` shows `skipped`
* Send a payload with missing `$.issue.fields.project.name` — verify no exception, `TriggerLog` shows `skipped`
* Disable the Trigger and resend the matching payload — verify no Ticket created
* Verify Django admin lists Triggers and Actions with enable/disable capability
