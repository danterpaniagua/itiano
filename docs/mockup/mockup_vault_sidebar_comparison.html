Design review · vault credential browsing

Sidebar navigation — two layouts, compared

Both render the real container tree (Operaciones's shared credentials, plus GCP and a nested Backups container) using the app's existing Bootstrap chrome — this is what will actually ship, not a redesign. The only variable being tested is how the container tree behaves on a narrow viewport.

1 Stacked sidebar

Matches the existing pattern from Notes (note_list.html) exactly: a col-md-3 sidebar beside the content on desktop, which becomes a full-width block that stacks above the credential list on mobile — no new interaction pattern introduced anywhere in the app.

Works in favor
  • Zero new patterns — identical to Notes today
  • Nesting (Azure Prod → Backups) reads naturally as indentation
  • Least implementation and review risk
Works against it
  • On mobile, a longer tree pushes real content below the fold
  • Tree and results compete for the same vertical space
2 Horizontal chip strip on mobile

Desktop is identical to Option 1. On mobile, the tree collapses to a single scrollable row of chips instead of a stacked list — the credential list is visible immediately below the fold, at the cost of a pattern not used anywhere else in the app yet.

  • Tree and results never compete for vertical space
Works against it
  • Nesting shown only as a "↳" prefix — reads as flat, not a tree
  • New interaction pattern, no precedent elsewhere in the app
  • A deep or wide tree could need real horizontal scrolling to reach
