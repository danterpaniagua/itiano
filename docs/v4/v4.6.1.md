# v4.6.1 — Docker Health Check + Graceful Shutdown

## Goal

Add a `/health/` endpoint for Docker health checks and configure Gunicorn and Docker Compose for graceful shutdown so in-flight requests complete before the container exits.

## In Scope

- `GET /health/` view in `core` — checks DB connectivity via `connection.ensure_connection()`; returns `200 {"status": "ok"}` or `503 {"status": "error"}`; no authentication required
- URL wired in `core/urls.py`
- `HEALTHCHECK` in `Dockerfile` using Python urllib (no extra packages needed); `--start-period 30s` to allow for migrations on boot
- `healthcheck` block in `docker-compose.yml` for the `app` service
- `stop_grace_period: 40s` in `docker-compose.yml` so Docker waits longer than the graceful timeout before force-killing
- Gunicorn `--timeout 30` and `--graceful-timeout 30` in `entrypoint.sh`

## Out of Scope

- External service checks (Jira, Redis, etc.)
- Readiness vs liveness distinction
- Metrics endpoint

## Technical Changes

- `core/views.py` — `health` view
- `core/urls.py` — `path('health/', views.health, name='health')`
- `Dockerfile` — `HEALTHCHECK` instruction
- `docker-compose.yml` — `healthcheck` and `stop_grace_period` for `app` service
- `entrypoint.sh` — `--timeout 30 --graceful-timeout 30` added to gunicorn

## Acceptance Criteria

- [x] `GET /health/` returns `200` when DB is reachable
- [x] `GET /health/` returns `503` when DB is unreachable
- [x] No login required to access `/health/`
- [x] Docker reports container as healthy after start period
- [x] `docker stop` waits up to 40s before force-killing
