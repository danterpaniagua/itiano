# v4.7.2 — Credential Versioning

## Goal

Auto-snapshot credentials on every save, show a collapsed version history on the edit form, and label secret-field changes without exposing values.

## In Scope

- `CredentialVersion` model: snapshot of all plaintext fields + encrypted blobs, `version_number`, `changed_by`, `changed_fields`, `created_at`
- Migration `0002_credentialversion`
- `vault/signals.py`: `post_save` on `Credential` — compute `changed_fields`, create `CredentialVersion`
- `vault/apps.py`: `ready()` imports signals
- `credential_create`, `credential_edit`, `import_confirm` in `views.py`: set `credential._changed_by = request.user` before save
- `credential_edit` passes `history` queryset (latest 20) to template
- `credential_form.html`: collapsible version history section after the form

## Out of Scope

- Restoring a previous version
- Diffing encrypted fields (only "changed" label, no value diff)
- Admin history UI

## Technical Changes

- New model: `vault.CredentialVersion`
- New file: `vault/signals.py`
- Updated: `vault/apps.py`, `vault/views.py`, `vault/migrations/`, `vault/templates/vault/credential_form.html`

## Acceptance Criteria

- Every credential save creates a `CredentialVersion` row
- First version shows `changed_fields = "created"`
- Subsequent versions list changed plaintext field names and "password changed" / "private key changed" / "passphrase changed" for secret fields
- `changed_by` is the logged-in user
- Edit form shows a collapsed "Version history (N)" button; clicking expands the list
- Import creates versions with `changed_by` set

## Validation Plan

- Create a credential → check version 1 exists with "created"
- Edit a field → check version 2 lists the field name
- Change password → check "password changed" label
- Import via KeePass → check version created with user set
