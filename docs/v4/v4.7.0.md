# v4.7.0 – Credential Vault

## Goal

A KeePass-style credential manager. Users store encrypted credentials with personal or team visibility. Supports three credential types: passwords, SSH keys, and certificates. Secrets are never rendered in plaintext — copy-to-clipboard only via AJAX. Each user has their own encryption key.

## In Scope

### Models

* `Team` — `name` (CharField), `members` (ManyToManyField → User). Introduced in `vault` app; extractable to `itsm` or `core` later.
* `UserVaultKey` — `user` (OneToOneField), `encrypted_key` (TextField). Stores a random 32-byte Fernet key encrypted with the app `SECRET_KEY`. Created on first vault access.
* `Tag` — `name` (CharField, unique).
* `Credential` — common fields: `owner` (FK User), `team` (FK Team, nullable), `visibility` (choices: `personal` / `team`), `credential_type` (choices: `password` / `ssh_key` / `certificate`), `name`, `notes` (TextField, blank), `tags` (ManyToManyField → Tag), `expiry_date` (DateField, nullable), `created_at`, `updated_at`.
  * **Password** fields: `url`, `username`, `encrypted_password` (TextField).
  * **SSH Key** fields: `encrypted_private_key` (TextField), `public_key` (TextField, blank), `encrypted_passphrase` (TextField, blank).
  * **Certificate** fields: `certificate_pem` (TextField, blank — public, not encrypted), `encrypted_private_key` (TextField, shared with SSH key type).
  * All encrypted fields blank by default; only the relevant ones are populated per type.

### Encryption

* `vault/crypto.py` — helpers: `get_user_fernet(user)` (creates `UserVaultKey` if absent), `encrypt_for_user(user, plaintext)`, `decrypt_for_user(user, token)`.
* Key-of-keys: `UserVaultKey.encrypted_key` is itself encrypted with a Fernet key derived from `SECRET_KEY` via SHA-256 (same pattern as clipboard).

### Views and URLs

* `GET /vault/` — list credentials visible to the user (personal owned + team credentials where user is a member).
* `GET/POST /vault/new/` — create credential.
* `GET/POST /vault/<pk>/edit/` — edit credential (owner only).
* `POST /vault/<pk>/delete/` — delete credential (owner only).
* `POST /vault/<pk>/copy/` — AJAX: decrypt and return the relevant secret based on type: `{"secret": "..."}`. For passwords: decrypted password. For SSH keys: decrypted private key. For certificates: decrypted private key. Requires ownership or team membership. CSRF enforced.

### UI

* Mobile-first list: name, type badge, username/URL (passwords) or key fingerprint hint (SSH), visibility badge, expiry warning if within 30 days.
* Credential form is type-aware: selecting the type shows/hides the relevant fields via JS.
* Secret fields (password, private key, passphrase): always `type="password"` — no show/hide toggle.
* Public key and certificate PEM: shown as read-only `<pre>` blocks (not secret).
* Copy button calls `/vault/<pk>/copy/` via fetch, writes decrypted secret to `navigator.clipboard`.
* Tag filter on list page.
* Expiry date shown with warning badge if ≤ 30 days away.
* Dashboard card: count of credentials owned by the user.
* Navbar link: `/vault/`.

### Docs

* `vault/templates/vault/docs.html` — fragment with usage and SECRET_KEY rotation warning.
* Tab added to `core/templates/core/docs.html`.

## Out of Scope

* TOTP / 2FA secret storage
* Credential history / versioning
* Password generator
* Import/export (CSV, KeePass XML)
* Admin-level visibility (staff sees all)
* Team management UI (teams created via Django admin)
* Per-field encryption (username/notes/public_key/certificate_pem stored plaintext; only secrets encrypted)
* SSH key generation (user must paste their own keys)

## Acceptance Criteria

* User can create personal and team credentials for all three types.
* Secret fields never show plaintext in the UI.
* Copy button writes the decrypted secret to clipboard.
* Non-member cannot access a team credential via direct URL (403).
* Non-owner cannot edit or delete a credential (403).
* Expiry warning badge appears when expiry ≤ 30 days.
* Tag filter narrows the credential list.
* Dashboard card shows correct count.
* DB encrypted fields contain ciphertext, not plaintext.
* Public key and certificate PEM are readable in the UI without copying.

## Validation Plan

* Create personal credential → verify only owner sees it.
* Create team credential → add second user to team → verify second user sees it.
* Inspect DB row → verify `encrypted_password` is ciphertext.
* Click copy → verify clipboard receives correct plaintext password.
* Access `/vault/<pk>/copy/` as non-member → verify 403.
* Set expiry to today+20 days → verify warning badge appears.
* Filter by tag → verify list narrows correctly.

## Security Notes

* `copy` endpoint must verify ownership or team membership before decrypting.
* CSRF token required on all POST/AJAX calls.
* All secret fields (`encrypted_password`, `encrypted_private_key`, `encrypted_passphrase`) encrypted with user's personal Fernet key, not the app-wide key.
* Rotating `SECRET_KEY` invalidates all `UserVaultKey` records → all credentials become unreadable. Document in docs section.
