# v4.7.4 — Jira Webhook Fixes + Diagnostic Logs

## Goal

Fix a production DataError caused by Jira payloads with long changelogs, add the missing automations migration, and add INFO-level logs to the webhook for request visibility.

## In Scope

- Truncate `JiraEvent.summary` to 500 chars in `_build_summary`
- Truncate `JiraTicket.title`, `project_key`, `issue_type`, `status` at DB limits in `update_or_create`
- Generate migration `automations/0007` for `description_format` choices (`jira_wiki` added) and `field_mappings` help_text change
- Add `jira_webhook_post_received` INFO log (fires before signature check): content length, has_signature, remote_addr
- Add `jira_webhook_payload_parsed` INFO log: event_type, issue_key, has_issue

## Out of Scope

- Changing field types to TextField
- Any other webhook behaviour changes

## Technical Changes

- Updated: `jira_integration/views.py`
- New: `automations/migrations/0007_alter_action_description_format_and_more.py`

## Acceptance Criteria

- Jira payloads with changelogs longer than 500 chars no longer cause DataError
- Docker startup shows no migration warnings for automations
- Every POST to `/jira/webhook/` produces an INFO log entry
