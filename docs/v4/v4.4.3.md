# v4.4.3 – Automation Fixes: Log Detail View + TicketEvent Field Overflow

## Goal

Two bug fixes:
1. `TicketEvent.old_value` and `new_value` overflow when ticket descriptions exceed 500 characters (Jira payloads).
2. Trigger log entries have no frontend detail view — errors are only visible in Django admin.

## In Scope

### TicketEvent field overflow

* Change `old_value` and `new_value` from `CharField(max_length=500)` to `TextField` in `itsm/models.py`.
* Migration to alter the columns.
* No change to `field_name` (max_length=100 is sufficient).

### Trigger log detail view

* `GET /automations/logs/<pk>/` — detail view for a `TriggerLog` entry.
* Shows: trigger name, action name, result badge, timestamp, error detail (if any), payload snapshot (formatted JSON).
* Link from the trigger log list to the detail view.
* Staff-only (same access level as the rest of Automations).

## Out of Scope

* Filtering or searching trigger logs
* Deleting trigger logs from the frontend
* Real-time log streaming

## Technical Changes

* `itsm/models.py` — `TicketEvent.old_value`, `TicketEvent.new_value` → `TextField`
* `itsm/migrations/` — new migration
* `automations/views.py` — `TriggerLogDetailView`
* `automations/urls.py` — new route
* `automations/templates/automations/trigger_log_detail.html` — detail template

## Acceptance Criteria

* Jira webhook with a long description creates/updates ticket without `value too long` error.
* Clicking a trigger log entry opens a detail page with result, timestamp, error detail, and formatted payload.
* Non-staff users cannot access `/automations/logs/<pk>/`.

## Validation Plan

* Send Jira webhook with description > 500 chars → verify ticket created/updated without error.
* Click a trigger log entry → verify detail page loads with correct data.
* Access `/automations/logs/<pk>/` as non-staff → verify 403.

## Delivered

### In-scope

* `itsm/models.py` — `TicketEvent.old_value` and `new_value` changed to `TextField`.
* `itsm/migrations/0006_ticketevent_text_fields.py` — migration for altered fields.
* `automations/views.py` — `log_list` annotated with `last_log_id`; `log_detail` view added.
* `automations/urls.py` — `/automations/logs/<pk>/` route added.
* `automations/templates/automations/log_list.html` — last result badge links to detail; detail column truncated to 80 chars.
* `automations/templates/automations/log_detail.html` — detail page: summary card, error detail card (if any), formatted payload snapshot.
