# v4.5.0 – Ticket Tags

## Goal

Tickets can be tagged. Tags can be assigned manually by users or automatically by Actions. Automation tags are replaced on each update; manual tags are preserved. Tags are visible on the ticket list and detail, and the list is filterable by tag.

## In Scope

### Models

* `Tag` — `name` (CharField, unique). Lives in `itsm`.
* `TicketTag` (through model) — `ticket` (FK), `tag` (FK), `source` (choices: `manual` / `automation`). Unique together on `(ticket, tag)`.
* `Ticket.tags` — `ManyToManyField(Tag, through=TicketTag, blank=True)`.

### Automations — field_mappings

* New key `"tags"` in `field_mappings`: accepts a list of JSONPath expressions.
* Each expression is resolved against the payload:
  * Scalar result → one tag
  * Array result → one tag per element
* On create: all resolved tags added with `source='automation'`.
* On update: delete existing `source='automation'` tags for the ticket, add new resolved ones. Manual tags untouched.
* `field_mappings` help text updated with `tags` documentation.

### Ticket List

* Tags shown as small badges on each ticket row (desktop + mobile card).
* Tag filter: dropdown of all tags. Filters the list to tickets that have that tag.

### Ticket Detail

* Tags section below the metadata row.
* Manual tag management: add existing tags via a select input; remove tags with an × button. Each add/remove POSTs to a dedicated endpoint.

### Admin

* `Tag` registered in `itsm/admin.py`.

## Out of Scope

* Creating new tags from the ticket detail (tags must exist or be auto-created by automation)
* Tag color / category
* Bulk tag operations
* Tag management UI (tags auto-created by dispatcher; manual creation via Django admin)

## Technical Changes

* `itsm/models.py` — `Tag`, `TicketTag`, `Ticket.tags`
* `itsm/migrations/` — new migration
* `itsm/admin.py` — register `Tag`
* `itsm/views.py` — tag filter on `TicketListView`; `ticket_tag_add` and `ticket_tag_remove` POST endpoints
* `itsm/urls.py` — two new tag endpoints
* `itsm/templates/itsm/ticket_list.html` — tag badges + tag filter
* `itsm/templates/itsm/ticket_detail.html` — tags section with add/remove
* `automations/dispatcher.py` — resolve `tags` key, upsert `TicketTag` with `source='automation'`

## Acceptance Criteria

* Action with `"tags": ["$.issue.status.name", "$.issue.labels"]` creates tags on the ticket.
* Re-running the webhook replaces automation tags but leaves manual tags intact.
* Ticket list shows tag badges per ticket.
* Filtering by tag shows only tickets with that tag.
* User can add/remove manual tags on the ticket detail page.
* Manual tags survive an automation update.

## Validation Plan

* Send webhook → verify automation tags created on ticket.
* Add manual tag → resend webhook → verify manual tag still present, automation tags updated.
* Filter ticket list by tag → verify correct results.
* Add and remove a manual tag from ticket detail → verify changes persist.
