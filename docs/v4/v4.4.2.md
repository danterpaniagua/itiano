# v4.4.2 – Clipboard Maximize/Minimize + Requester Field Mapping

## Goal

Two fixes:
1. Clipboard offcanvas gains a maximize/restore toggle button.
2. `requester` key in `Action.field_mappings` is resolved and stored as `creator_name` on the ticket (currently silently ignored).

## In Scope

### Clipboard maximize/minimize

* Maximize button in the offcanvas header: expands the panel to full viewport width and height.
* Restore button (same toggle): returns to the default offcanvas size (420px wide).
* Toggle is client-side only — no backend changes.

### Requester field mapping

* `automations/dispatcher.py` — `_resolve_fields` reads `requester` key from `field_mappings` and maps it to `creator_name`, falling back to `creator` if both are present.
* No model or migration changes — `creator_name` field already exists on `Ticket`.

## Out of Scope

* Persisting maximize state across page loads
* Keyboard shortcuts for maximize/minimize
* Resizable offcanvas (drag to resize)

## Technical Changes

* `core/templates/base.html` — add maximize/restore button to offcanvas header; JS toggle to switch between full-screen and default size.
* `automations/dispatcher.py` — `_resolve_fields` updated to handle `requester` → `creator_name`.

## Acceptance Criteria

* Clicking maximize expands the offcanvas to fill the viewport.
* Clicking restore returns it to 420px width.
* Action with `"requester": "$.user.displayName"` in `field_mappings` stores the resolved value in `creator_name` on the created/updated ticket.

## Validation Plan

* Open clipboard offcanvas → click maximize → verify full-screen.
* Click restore → verify 420px width returns.
* Send Jira webhook with `requester` mapping → inspect ticket `creator_name` field.

## Delivered

* `core/templates/base.html` — maximize/restore button added to offcanvas header; `ocToggleMaximize()` toggles between full viewport size and default 420px; icon switches between `bi-fullscreen` and `bi-fullscreen-exit`.
* `automations/dispatcher.py` — `_resolve_fields` now reads `requester` key from `field_mappings` and uses it as `creator_name`, falling back to `creator` if absent.

## Related Scope Dependencies

* v4.4.0 — clipboard offcanvas introduced
* v4.2.0 — `creator_name` field on Ticket
