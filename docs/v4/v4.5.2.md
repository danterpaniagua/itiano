# v4.5.2 — Resend Jira Event to Automations

## Goal

Allow staff users to re-dispatch any stored Jira event payload through the Automation pipeline without waiting for a new webhook from Jira.

## In Scope

- `resend_event` view — POST, staff-only; re-dispatches a `JiraEvent` payload via `dispatch(source='jira', payload=event.payload)`; does not create a new `JiraEvent`
- Resend button on each event row in the event log (ticket detail page)
- Resend button in the header action bar for the last received event

## Out of Scope

- New `JiraEvent` record on resend
- Email or push notifications on resend
- Non-staff users triggering resends

## Technical Changes

- `jira_integration/views.py` — add `resend_event(request, issue_key, event_pk)`
- `jira_integration/urls.py` — add `<str:issue_key>/resend/<int:event_pk>/`
- `jira_integration/templates/jira_integration/ticket_detail.html` — resend POST form buttons

## Acceptance Criteria

- [ ] Staff user can resend any event from the event log
- [ ] Staff user can resend the last event from the header
- [ ] Non-staff users do not see the resend button
- [ ] Resend re-runs automations with the stored payload
- [ ] No new `JiraEvent` is created on resend
- [ ] User is redirected back to the ticket detail page after resend

## Validation Plan

Run tests: `docker compose exec app python manage.py test jira_integration`
