# v4.0.0 – Documentation Hub + Ticket Audit Log

## Goal

Two platform upgrades in one major release: a centralized documentation page accessible to all users, and a full field-level audit log for tickets with a redesigned tabbed ticket detail UI.

## In Scope

### Feature 1 — Centralized Documentation

* `/docs/` view in `core` — tabbed layout, all authenticated users
* Tabs: Tickets, Jira Integration, Automations, Sandbox
* Each app contributes its own section via `<app>/templates/<app>/docs.html`; central page assembles with `{% include %}`
* **Tickets tab** — ticket types, states, priorities, roles
* **Jira Integration tab** — webhook setup, payload path reference
* **Automations tab** — filter operator reference (moved from sandbox inline table)
* **Sandbox tab** — JSONPath syntax and usage tips
* Nav link "Docs" in `base.html` for all authenticated users
* `json_sandbox/sandbox.html` — replace inline operator table with link to `/docs/#automations`

### Feature 2 — Ticket Audit Log + Edit View

* `TicketEvent` extended with `field_name`, `old_value`, `new_value` (CharField max 500, blank=True)
* New ticket edit view `/tickets/<pk>/edit/` — staff and assigned agent only; editable fields: `title`, `description`, `type`, `priority`, `category`, `service`, `sub_service`
* Field change detection before save: one `TicketEvent` per changed field with `field_name`, `old_value`, `new_value`
* Tracked fields: `title`, `description`, `type`, `priority`, `assigned_to`, `category`, `service`, `sub_service`, `creator_name`
* State transitions continue using `from_state`/`to_state` — no change to transition logic
* Ticket detail page converted to Bootstrap tabs: **Details**, **Comments**, **Log**
  * Details — description, metadata, action buttons (state transitions)
  * Comments — existing thread + add comment form
  * Log — all `TicketEvent` records (transitions + field changes) in reverse chronological order
* Mobile-first tabs on all screen sizes

## Out of Scope

* Reverting field changes
* Tracking changes made via Django admin or ORM directly
* Per-field visibility permissions
* Search within docs
* Markdown rendering in docs
* Public (unauthenticated) access to docs
* Editing `assigned_to` via the edit form (assignment happens via transition)

## Acceptance Criteria

* `/docs/` accessible to all authenticated users; all four tabs render
* Automations operator reference visible in Automations tab; removed from sandbox inline
* Ticket edit view accessible to staff and assigned agent; other roles receive 403
* Editing priority creates a `TicketEvent` with `field_name="priority"`, correct `old_value` and `new_value`
* Unchanged fields produce no `TicketEvent`
* Log tab shows state transitions and field changes in reverse chronological order
* Existing state transition behaviour unaffected
* All pages mobile-first: no horizontal scroll, tabs visible on small screens

## Validation Plan

* Access `/docs/` as non-staff — verify page loads with all tabs
* Verify Automations tab shows operator reference
* Verify sandbox Filter panel links to `/docs/` instead of inline table
* Edit a ticket's priority — verify `TicketEvent` created with correct field/values
* Edit a ticket without changing anything — verify no extra `TicketEvent` created
* Transition a ticket state — verify Log tab shows both the transition and any prior field changes
* Access `/tickets/<pk>/edit/` as requester — verify 403
* Resize to mobile — verify tabs and forms render without horizontal scroll
