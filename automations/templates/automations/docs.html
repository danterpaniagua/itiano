Automations

Automations listen for incoming webhook payloads and create tickets when a filter condition matches.

Concepts
  • Action — Defines what to do (e.g., create a ticket) and how to map payload fields.
  • Trigger — Defines when to act: a source (e.g., Jira) and a filter condition.
  • Filter — A JSON condition tree evaluated against the incoming payload.
Filter Structure

Filters use a JSON AST with logical combinators and leaf conditions:

{
  "and": [
    {"path": "$.webhookEvent", "op": "eq", "value": "jira:issue_created"},
    {"path": "$.issue.fields.labels", "op": "in", "value": ["PROD", "Azure"]}
  ]
}
Operators
OperatorUse case
eqExact match
eq_ciCase-insensitive match
neqNot equal
inAny label in list (exact)
in_ciAny label in list (case-insensitive)
not_inNo label in list (exact)
not_in_ciNo label in list (case-insensitive)
containsSubstring match
existsField is present and non-empty (no value needed)
regexAny label matches regex pattern
Tag Expressions

Actions can stamp colored tags on created tickets. Each expression row has a JSONPath and a color (Bootstrap palette or custom hex):

[
  {"expression": "$.issue.fields.labels[*]", "color": "#ffc107"},
  {"expression": "$.issue.fields.status.name", "color": "#198754"}
]
  • A JSONPath that returns multiple values (e.g. [*]) creates one tag per value.
  • Tag color is updated on the Tag record each time the automation fires.
  • Tags created by automations are marked with 🤖 on the ticket.
Trigger Identity Tag

Each Trigger can have a single Trigger Tag — a static ITSM tag stamped on every ticket the trigger creates or updates.

  • Set it in the Trigger Tag field on the trigger edit form. The field pre-fills with the current tag name on reopen.
  • Leave blank to remove the tag association.
  • On the ticket, automation tags (both dynamic from tag_expressions and the trigger identity tag) are marked with 🤖.
  • Use this to identify which automation originated a ticket — e.g. auto-infradevops.
Save vs Apply

The Action and Trigger edit forms have two submit buttons:

  • Save — saves and returns to the list.
  • Apply — saves and stays on the edit page. Useful when iterating on tag colors or field mappings without losing your place.

Both buttons are disabled until a change is detected in the form.

Field Mappings

In an Action, field_mappings maps ticket fields to JSONPath expressions or literal values:

{
  "title":       "$.issue.fields.summary",
  "description": "$.issue.fields.description",
  "type":        "incident",
  "priority":    "$.issue.fields.priority.name",
  "creator":     "$.user.displayName",
  "service":     "$.issue.fields.project.name"
}

Values starting with $. are resolved via JSONPath. All others are used as literals.
